# ADR-0001: 백엔드를 Node.js + TypeScript로 마이그레이션한다

- 상태: accepted
- 날짜: 2026-08-14

## 맥락

백엔드는 Java 21 + Spring Boot 4로 작성되어 운영 중이다(`backend-java/`).
프론트엔드는 React 19 + TypeScript이며, 팀의 주 언어와 도구 체인(Biome·Vitest·
TS 타입 시스템)이 JS 생태계에 있다. 실시간 게임 서버의 핵심 로직(와이어 계약,
게임 규칙, 상태 동기화)은 프론트와 타입·용어를 공유하는데, 언어 경계 때문에
같은 계약을 양쪽에서 중복 정의하고 있다(`wsEvents.ts` ↔ Java DTO).

## 결정

백엔드를 Node.js + TypeScript로 재작성한다. 기존 Java 백엔드는 `backend-java/`로
이동해 참조 구현으로 동결하고, 마이그레이션 완료 후 제거한다.

## 근거

- 프론트·백이 단일 언어가 되어 와이어 계약(`wsEvents.ts`)을 장기적으로 공유
  타입으로 통합할 수 있다.
- 팀의 검증 도구(Vitest·Biome·Playwright)가 그대로 백엔드에 적용된다.
- 이 서비스의 백엔드 부하 특성은 I/O 바운드(WS 브로드캐스트, Redis 왕복)로
  Node 런타임과 잘 맞는다. CPU 바운드 요소(물리 시뮬레이션)는 설계상 서버에
  없다(DESIGN.md 핵심 원칙 2).

## 검토한 대안

- **Java 유지**: 운영 리스크는 없지만 언어 이중화 비용이 계속 발생한다.
- **Kotlin 전환**: JVM 유지로 이식 비용은 낮지만 프론트와의 언어 통합 목표를
  달성하지 못한다.
- **부분 포팅(게임 서버만 Node)**: 두 백엔드를 동시 운영하는 기간이 길어지고
  세션·인증을 이중으로 관리해야 해 기각.

## 결과

- 마이그레이션 기간 동안 두 백엔드가 공존한다. 운영은 backend-java, 개발은
  backend에서 진행하며 전환 계획은 [PLANS.md](../../PLANS.md)를 따른다.
- Java에 축적된 동작 지식(테스트 포함)이 명세가 된다 — 테스트를 함께 이식한다.
