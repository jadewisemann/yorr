# ADR-0002: 와이어 계약을 동결하고 수직 슬라이스로 이식한다 (strangler)

- 상태: accepted
- 날짜: 2026-08-14

## 맥락

백엔드 재작성은 실패 위험이 가장 큰 종류의 작업이다. 재작성 중에도 서비스는
운영되고, 프론트엔드는 이미 REST + WebSocket 계약(`frontend/src/realtime/wsEvents.ts`,
프로토콜 버전 1)에 맞춰 완성되어 있다.

## 결정

1. **와이어 계약 동결.** 새 백엔드는 backend-java와 같은 REST 경로·응답 모양,
   같은 WebSocket 메시지를 구현한다. 프론트엔드 프로덕션 코드는 마이그레이션으로
   변경되지 않는다. 계약 검증의 최종 수단은 프론트 E2E(`test:e2e:real`)다.
2. **수직 슬라이스 이식.** 레이어(컨트롤러 전부 → 서비스 전부)가 아니라 기능
   단위(로비 → 게임 프레임워크 → 게임 하나씩)로 끝까지 이식하고 실제 클라이언트로
   검증한다. 순서는 [PLANS.md](../../PLANS.md).
3. **backend-java 동결.** 이식 중 원본이 움직이면 명세가 흔들린다. 운영 hotfix는
   별도 브랜치로 격리하고, 발생 시 이식 대상 목록에 반영한다.

## 검토한 대안

- **빅뱅 재작성 후 일괄 전환**: 검증이 마지막에 몰려 실패를 늦게 발견한다. 기각.
- **계약 개선을 겸한 재작성**(예: envelope의 게임 무관화): 재작성과 계약 변경이
  섞이면 회귀의 원인을 분리할 수 없다. 계약 개선은 마이그레이션 완료 후 별도
  작업으로 미룬다.
- **양 백엔드 동시 운영(경로별 라우팅)**: 세션·방 상태가 Redis에서 공유되어야
  해 결합이 크다. 전환은 게임 단위가 아니라 배포 단위로 한다(Phase 5).

## 결과

- "동작이 같은가"가 모든 이식 티켓의 완료 조건이 된다. Java 쪽 버그도 일단
  기록 후 재현하는 것이 기본값이다(고칠지는 명시적 결정).
- 프론트 `wsEvents.ts`의 알려진 문제(야추 타입 결합)도 그대로 구현한다 —
  계약 정리는 이 마이그레이션의 범위 밖이다.
