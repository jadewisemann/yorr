## 2026-10-19 - PR #79 코드 리뷰에서 확인한 결함

- **SQLite `release()`가 ROLLBACK 실패 시 전역 잠금을 놓지 않았다.** COMMIT이 실패해 SQLite가
  스스로 되돌린 뒤 ROLLBACK을 다시 하면 "no transaction is active"로 던지고, 그 뒤의 모든 질의가
  영원히 기다렸다. 수정 전 코드에서 재현 테스트 4건이 전부 매달리는 것으로 확인했다.
- **스크립트 인자를 빈 문자열로 채우는 것은 위험했다.** TTL 인자를 빠뜨리면 `expire(key, '')`가
  `Number('') = 0`이 되어 방금 만든 키를 지웠다(Lua는 "not an integer"로 던졌다). 스크립트마다
  키·인자 개수를 선언하고 정확히 검사하며, 정수 인자는 Redis처럼 정수 문자열만 받는다.
- **`ZRANGE`의 음수 stop이 길이를 넘으면 틀렸다**(`0 -5`가 앞부분을 돌려줬다). Redis 색인 규칙을
  기준 구현으로 옮겨 길이 0~4 × 범위 [-6, 6]을 전수 대조한다.
- **인증 없는 게스트 생성으로 힙을 다 쓸 수 있었다.** 외부 Redis가 받아 주던 것을 128MB 힙이 받는다.
  키 수 상한(10만, 실측 힙 80MB 미만)에서 새 키를 거절한다(`noeviction`).
## 2026-10-18 - 봇 AI를 0.5 vCore에 맞추며 발견한 것

- **Node의 timers 단계는 만료된 타이머를 전부 돌린 뒤에야 I/O로 간다.** 여러 방의 봇 턴이 같은
  시점에 만료되면 탐색 N개가 연달아 돌고 그동안 다른 소켓이 전부 기다린다(번들·CPU 50%·방 30개에서
  ping 최대 506ms). 예전 yacht.md는 "타이머가 따로라 사이에 I/O가 끼어든다"고 적었는데 틀렸다.
  `CooperativeYachtBotPolicy`로 직렬화하고 탐색 사이마다 `setImmediate`로 양보한다 → 93ms.
- **같은 프로세스 안에서는 굶김을 잴 수 없다.** 클라이언트의 타이머도 함께 막혀 왕복이 1ms로 나온다.
  굶김 측정은 서버를 별도 프로세스로 띄우고 밖에서 잰다(`test/load/starvationServer.ts`).
- **부하 측정이 한때 거짓 초록이었다.** 턴 순서가 호스트 우선이라, 아무것도 안 하는 호스트의 25초
  타임아웃 동안 봇이 하나도 움직이지 않았다(봇 150명에 ping p99 0.7ms). 호스트 자동 진행을 붙이고
  "봇이 실제로 굴린 횟수"를 단언으로 넣었다.
- **오라클 대조가 주석의 거짓을 잡았다.** "스몰 스트레이트 충족 시 초이스 제외"는 결정을 바꾸는
  규칙인데 "순수한 가지치기"라고 적혀 있었다. 동작은 이식 테스트가 요구하므로 유지했다(yacht.md).

## 2026-10-18 - 저장소·DB를 프로세스 안으로 옮기며 발견한 것 (ADR-0007)

- **ioredis-mock은 운영 드라이버로 못 쓴다.** fengari가 Lua 호출마다 상태를 새로 만들어
  빈 스크립트 한 번에 1.2ms, 2,000번에 RSS 262MB가 늘었다. 그래서 Lua를 동기 JS 함수로 옮겼다.
  ioredis-mock은 만료 키를 다시 조회할 때만 지우고, Lua 실행 중에 시각이 흐르며, 같은
  프로세스의 인스턴스끼리 키 공간을 공유한다 — 셋 다 `MemoryRedis`에서는 해당 없다.
- **인메모리 저장소는 마이크로태스크로 즉시 답한다.** 진짜 Redis는 명령마다 네트워크 왕복이라
  그 사이 타이머가 돌았다. 지금은 `await`만 반복하고 `setTimeout`이 없는 루프가 있으면 이벤트
  루프가 완전히 멈춘다(테스트 타임아웃조차 발동하지 않는다). 상태 저장소의 스핀 잠금은
  재시도마다 `delay`를 두고 있어 안전하다. 새 루프를 쓸 때 이 점을 본다.
- **Node의 재귀 `mkdirSync`는 `/proc` 아래에서 끝나지 않는다.** "열 수 없는 DB 경로"를 시험하려고
  `/proc/...`를 썼다가 테스트 파일 하나가 CPU 100%로 매달렸다. `/dev/null/...`(즉시 ENOTDIR)을 쓴다.
- **`node:sqlite`는 동기식이다.** 여러 테스트 워커가 같은 DB 파일을 잡으면 잠금을 기다리는 동안
  이벤트 루프가 멈춘다. 서버를 띄우는 테스트는 `SQLITE_PATH: ':memory:'`를 넘긴다(TESTING.md 규칙 5).
- **누수 검사가 "시작 전과 같음"을 요구하면 틀린다.** 테스트 시작 시점에 vitest 내부의 일시
  타이머가 하나 떠 있다가 사라진다. Redis 연결 정리가 느리던 시절에는 우연히 가려졌다. 지금은
  "시작 전보다 늘어난 자원이 없다"를 본다 — 서버를 닫지 않게 망가뜨리면 여전히 잡힌다.
- **`npm start` 래퍼는 RSS 약 65MB를 따로 쓴다.** Botkeep 시작 명령에는 `node ...`를 직접 넣는다.

## 2026-08-25 - www.yorr.site가 허용 목록에 없어 로그인이 안 됐다

- **증상은 또 "로그인이 안 된다"였고, 원인은 또 복귀 출처였다.** 8/21 메모가 만든
  구조(`origin`을 실어 보내고 `state`가 왕복시킨다)는 정상 동작했다. 걸린 곳은 그
  구조가 참조하는 **목록**이다: 사용자가 `https://www.yorr.site`에서 로그인을
  시작했는데(authorize 요청이 `?origin=https%3A%2F%2Fwww.yorr.site`였다) 목록에는
  apex(`https://yorr.site`)만 있었다. `resolveReturnUrl`이 미등록 출처를 조용히
  설정값으로 되돌리므로 로그인은 apex로 돌아갔고, 세션은 apex의 localStorage에
  저장돼 www에서는 계속 로그아웃으로 보였다.
- **원인은 도메인 전환 절차의 1번을 실제로는 밟지 않은 것이다.** operations.md의
  「프론트 도메인 전환」 1번은 apex와 www 중 하나를 primary로 두어 나머지에 301을
  걸라고 적어 두었고, 2번은 "301을 걸지 않으면 www도 목록에 넣어야 한다"는 조건을
  달아 두었다. Vercel에서 301이 걸리지 않은 채 두 이름이 모두 서비스됐고, 그
  조건절이 발동한 것을 아무도 알아채지 못했다. **조건부로 적힌 설정은 그 조건이
  실제로 어느 쪽인지 확인되기 전까지 아무 일도 하지 않는다.**
- **한 목록이 세 가지를 동시에 정한다** — REST CORS · WS 핸드셰이크 `originAllowed`
  · 로그인 복귀 출처. 그래서 www 사용자는 로그인만 막힌 것이 아니라 REST가 403이고
  WS도 거절됐다. 셋의 증상이 사용자에게는 구분되지 않는다.
- 고친 것은 `deploy/compose.yaml`의 `CORS_ALLOWED_ORIGINS` 기본값 한 줄이다
  (www 추가). 코드에는 손대지 않았다 — 8/21 구조가 이미 맞았다. 호스트에서 할 일은
  `git pull` + `docker compose up -d backend`뿐이다.
- **판단 근거를 남긴다: 301 쪽으로 고치지 않았다.** 어느 이름을 정본으로 삼을지는
  Vercel 대시보드의 결정이고 저장소 밖이다. 목록에 www를 더하는 쪽은 301을 나중에
  걸어도 안전하며(그때 목록에서 빼면 된다), 지금 로그인을 즉시 되살린다.

## 2026-08-21 - 로그인 복귀 출처를 여러 개로 (state가 실어 나른다)

- **문제는 "yorr.site로만 로그인된다"였다.** 백엔드는 공인 IP + IP 인증서로 돌고
  카카오·구글 콘솔은 IP를 Redirect URI로 받지 않는다. 그래서 콜백만 프론트
  도메인으로 받아 Vercel rewrite로 넘기는데(#40), 그 도메인이 `yorr.site` 하나라
  `yorr-eight.vercel.app`에서 로그인하면 `AUTH_FRONTEND_REDIRECT_URI`(=yorr.site)로
  튕겼다. **세션은 출처별 localStorage라 튕긴 쪽에서는 로그아웃으로 보인다** —
  증상이 "로그인이 안 된다"라서 원인이 복귀 주소라는 게 잘 안 보인다.
- **제공자가 콜백으로 돌려주는 것은 `state`·`code`·`error`뿐이다.** redirect_uri에
  파라미터를 덧붙여 출처를 왕복시키려 했지만 콘솔 등록값과 문자 하나까지 같아야
  해서(카카오 KOE006) 불가능했다. 남는 자리는 `state` 하나였고, 그래서 state의
  값이 `"1"`에서 **복귀 주소**로 바뀌었다. 1회용 시맨틱은 DEL →
  GETDEL로 옮겨 그대로 유지된다(`LoginCodeStore`와 같은 모양이 됐다).
- **판정 순서는 지켰지만 소비 시점을 앞으로 옮겼다.** `error → state → code`라는
  응답 계약은 그대로다(실패 사유 우선순위 불변). 달라진 것은 취소된 콜백도 state를
  태운다는 것 하나인데, 취소한 사용자는 authorize부터 다시 시작하므로 그 state를
  쓸 곳이 없다. 이 대가를 받은 이유는 **실패 응답도 시작한 출처로 돌아가야** 하고
  그 주소를 아는 곳이 state뿐이기 때문이다.
- **허용 목록을 CORS와 공유한다.** 전용 변수를 새로 만들려다 접었다 — 목록이 둘이면
  한쪽만 갱신되는 순간 증상이 "CORS는 되는데 로그인만 안 된다"가 되고, 그 조합은
  이 저장소가 이미 여러 번 밟은 자리다(도메인 전환 절). 대신 `*`는 여기서 받지
  않는다: WS 게이트웨이에서 와일드카드는 "누가 우리를 부를 수 있는가"지만
  복귀 주소에서는 "누구에게든 로그인 코드를 실어 보낸다"가 된다.
- 클라이언트가 고르는 것은 **출처뿐이다.** 경로·쿼리는 설정값에서 가져오고
  스킴·호스트만 갈아 끼운다(`auth/returnTo.ts`) — 경로까지 받으면 그 자체로
  오픈 리다이렉트가 된다.
- 프론트 테스트에서 `vi.stubGlobal('location', {...globalThis.location})`이
  `origin`을 **유지한다**(jsdom). 스프레드가 프로토타입 게터를 못 옮길 것으로 보고
  파라미터를 생략하는 분기를 넣었는데, 실제로는 유지되므로 그 분기는 브라우저가
  아닌 환경(SSR·노드)용 방어로만 남았다.

## 2026-08-21 - 연습 방 제한 시간 없애기 (와이어 계약 변경 1건)

- **계약이 바뀐다.** `round.start`의 `deadline`과 재접속 스냅샷의
  `game.roundDeadline`이 `number | null`이 됐다. 동결 원칙의 예외이므로
  [PLANS.md](PLANS.md) 「연습 방 시계 제거」 절과
  [frontend/PLANS.md](../frontend/PLANS.md)에 계획을 상호 링크해 뒀다.
  프론트가 정본이라 `wsEvents.ts`를 먼저 고치고 서버를 맞췄다.
- **롤백하면 갈린다.** 직전 릴리스에는 이 동작이 없다 — 되돌리면 연습 방에도
  25초가 다시 걸린다. 프론트는 숫자 마감을 그대로 받아 타이머를 그리므로
  **깨지지는 않는다**(기능만 사라진다).
- 판정 기준을 "봇이 있는가"가 아니라 **"사람이 하나 이하인가"** 로 잡았다. 봇 없이 혼자
  시작한 방(YACHT_DICE는 minPlayers 1)도 기다리는 사람이 없기는 마찬가지다.
- **봇 턴의 폴백 예약은 남겼다.** 처음에는 연습 방의 모든 예약을 지웠는데,
  yacht.md 「실패 격리」가 "봇 스텝의 예외는 삼키고 라운드 타이머가 폴백"이라고
  못박고 있었다 — 예약까지 지우면 봇 굴림이 한 번 실패한 판을 깨울 것이 없어진다.
  그래서 **방송되는 deadline(null)과 내부 예약을 분리**했다. `currentDeadline`이
  3값(시각/null/undefined)이 된 것이 그 분리의 흔적이다.
- 기존 테스트 8개가 깨졌는데 전부 **대역의 방 명단이 비어 있어서**였다
  (`players: []` → 사람 0명 → 연습 방). 방 명단이 이제 시계의 입력이라는 뜻이라,
  대역 기본값을 사람 둘로 바꿨다(`humanRoster`). `serverWiring` 통합 테스트도
  같은 이유로 손님 하나를 더 붙였다 — 그 테스트가 보려던 것은 "레지스트리가 갈리면
  start가 null"이었는데, 연습 방도 null이라 신호가 겹쳤다.
