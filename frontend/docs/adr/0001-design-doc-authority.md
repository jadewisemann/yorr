# ADR-0001: 설계 문서를 정본으로 승격한다 (코드 우선 → 문서 우선)

- 상태: accepted
- 날짜: 2026-08-14

## 맥락

프론트엔드 문서는 완성된 코드에서 추출해 쓴 서술형 위키(`docs/llmwiki/`,
2026-08-13 전면 개편)였고, "문서와 코드가 충돌하면 항상 코드가 이긴다"를
원칙으로 삼았다. 코드가 유일한 진실일 때 문서 부패에 안전한 규칙이지만,
어긋남을 **발견했을 때만** 고치는 수동적 구조라 위키는 시간이 지나면 낡는다.

한편 백엔드는 JS 마이그레이션을 계기로 DESIGN.md 정본 체계(문서 우선 +
Understand→Implement→Reconcile 사이클)를 도입했다. 한 저장소에서 에이전트가
절반씩 반대 규칙으로 일하면 혼선이 생기고, 앞으로 작업 비중은 에이전트 쪽으로
늘어난다.

## 결정

1. `frontend/DESIGN.md`를 설계·불변식의 정본으로 둔다. `docs/llmwiki/`는 하위
   시스템 설계 문서 층으로 그 아래에 있다(백엔드 `docs/design/` 대응 —
   포트폴리오 등 기존 링크를 지키기 위해 폴더 이름은 유지한다).
2. 권위를 뒤집기 전에 **코드를 기준으로 동기화**했다. 기준선: 2026-08-13 위키
   개편(코드에서 추출) + 2026-08-14 구조 검증(디렉터리 구성, biome 경계 강제,
   순환 검사, 카탈로그·envelope 대조). 이 시점 이후 어긋남은 "판정 대상"이다 —
   조용히 코드를 따르지 않는다.
3. 예외: 기계가 소비하는 계약 파일(`wsEvents.ts`·`games.ts`·`scoring.ts`·
   `tokens.css`)은 계속 코드가 정본이다. 문서는 이들을 서술만 한다.
4. 문서는 사람과 에이전트가 **함께 수정**한다 — 사람은 의도가 바뀔 때,
   에이전트는 Reconcile 단계에서 현실을 반영할 때. 둘 다 PR 리뷰를 거친다.

## 검토한 대안

- **현행 유지(코드 우선)**: 부패를 사후에만 잡고, 에이전트가 매번 코드에서
  아키텍처를 역추론한다. 저장소 반쪽마다 규칙이 달라지는 문제도 남는다.
- **llmwiki → docs/design 개편**: 백엔드와 폴더 이름까지 맞추는 안. 포트폴리오
  문서 10곳의 링크를 깨고, 개편 하루 뒤에 구조를 다시 흔드는 churn이라 기각.
- **위키 전면 재작성**: 위키가 신선(하루 전)하고 검증을 통과해 불필요.

## 결과

- 읽기 순서가 바뀐다: 코드 탐색 전에 DESIGN.md → 관련 llmwiki 페이지.
- 작업 사이클에 Reconcile(문서 일관성 검토)이 의무가 되고, Claude Code에서는
  커밋 게이트 훅이 아키텍처 민감 영역에 대해 이를 1회 강제한다.
- `README.md` 등 사람용 문서의 "항상 코드가 이긴다" 문구는 이 결정에 맞게
  수정한다.
