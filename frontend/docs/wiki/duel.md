# 석양이 진다 (DUEL)

> SSOT: [`../../src/duel/`](../../src/duel/) — `screens/DuelGame.tsx`(진입점) ·
> `domain/stage.ts`(서버 상태 → 무대 번역) · `domain/duel.ts`(밸런스 상수) ·
> `components/Arena.tsx`(순수 표현)

1:1 반응속도 대결. 신호등이 초록이 되는 순간 먼저 뽑은 쪽이 쏜다. 3발 맞으면 쓰러지고,
신호 전에 뽑으면 경고가 쌓여 두 개면 자기 발을 쏜다. **규칙·판정은 전부 서버 소유** —
화면은 뽑은 순간의 반응 시간만 올리고, 서버 상태를 무대가 이해하는 그림으로 번역한다.

## 화면 분기

`dashboard` → Arena 관전 / `isPartyRoom(roomCode)` → 폰 컨트롤러(신호등 + 탄약·경고만) /
그 외 → Arena 전체 + 전면 탭 존. 폰에 무대를 축소해 넣지 않는다 — 같은 것을 두 화면에
그리면 폰을 보는 동안 TV의 연출을 놓친다.

## 반응 시간 측정 — 왕복 지연을 핸디캡으로 만들지 않기

- **각자 자기 화면 기준으로 잰다.** 신호를 처음 그리는 **렌더에서** 기준 시각을 잡는다 —
  effect까지 미루면 커밋과 effect 사이에 들어온 아주 빠른 탭이 부정출발로 신고된다.
  `game.duel.draw { inputSeq, reactionMs }`로 전송, 서버는 상한만 검증한다
  (`min(신고값, now - signalAt)` clamp).
- 부정출발은 센티넬 `-1`(FOUL), 무반응은 `-2`(MISS).

## 입력 밸런스 — 스윙 vs 손가락

폰을 휘두르려면 팔이 움직여야 하고 탭·스페이스바는 손가락만 움직인다 — 같은 반응속도로
재면 스윙이 구조적으로 진다. `DRAW_PENALTY_MS = { key: 100, swing: 0, tap: 100 }`
(실기기 튜닝 값).

- **페널티는 숫자를 키우는 게 아니라 전송을 늦춰서 건다.** 신고값만 키우면 서버 clamp가
  깎아 버려 왕복이 짧은 회선에서 페널티가 통째로 사라진다 — 밸런스가 회선 속도에 따라
  달라진다. 전송을 늦추면 서버 기준 시각도 밀려 깎이지 않는다. 상한은 서버 유예
  `GRACE_MILLIS`(700ms) — 넘기면 기다리는 동안 라운드가 끝난다.
- 센티넬 보호: 부정출발(-1)에 100을 더하면 99가 되어 최속 정상 기록으로 둔갑한다 —
  센티넬에는 페널티 0.
- **연출은 지금 한다.** 총소리·총알을 100ms 늦추면 고장난 것처럼 느껴진다 — 페널티는
  기록에 걸리고, 어느 입력이 빠른지는 컨트롤러 화면이 말로 알려 준다.
- 스윙 임계 15(`useSwing` 기본 14보다 높음). `enabled` 게이트를 걸지 않는 이유는
  [motion-input.md](./motion-input.md) 참고.

## 착탄 타이밍 — 로컬 예측 + 지각 보정

- 총알 비행시간은 무대 폭 기반 `flightMs` = 거리 ÷ 1.6px/ms, `[260, 420]` clamp — 시간을
  고정하면 폰에서는 기어가고 노트북에서는 순간이동한다. 하한이 260인 이유: 판정이
  도착하기 전에 총알이 닿으면 피격이 늘 총알보다 늦다(실측 63ms 지각).
- `useImpactDelay`는 판정 진입 렌더에서 **한 번만** 재고 붙잡는다 — 매 렌더 다시 재면
  CSS animation-delay가 바뀌어 재생 중인 연출이 앞으로 튄다. 내 총알이면 이미 날아간
  만큼을 깎는다. `IMPACT_LEAD_MS = 45` — setTimeout 후 렌더+페인트 한두 프레임 지각 보정
  (실측 50~60ms).
- 서버 시각(`lastRound.at`)이 아니라 로컬 타이머 — 두 기기의 시계가 맞다는 보장이 없다.

## 서버 상태 → 무대 번역 (`stage.ts`) 불변식

1. **나를 항상 왼쪽에** — 서버는 진영 번호를 주지 않는다(`playerOrder`뿐).
2. **인과 보정** — 총알이 닿기 전에는 맞은 쪽 hp를 한 칸 되돌린다. 서버 체력은 이미
   판정 끝난 값이지만, 총알이 나는 동안 체력이 먼저 깎이면 인과가 뒤집힌다.
3. **상대 총알·기록은 판정 후에만** — 유예 중에 상대가 뽑는 게 보이면 승부가 김이 샌다.
4. **비아냥은 결정론** — `missTaunt((round.number × 31) + reactions[misser])`. 난수를 쓰면
   두 사람이 다른 말을 보고, 재접속·리렌더에 말이 바뀐다.
5. 승패는 `koId`(쓰러진 사람이 진 사람) — 남은 총알로 따지면 부정출발 실격이 총알을 남긴
   채 이기는 걸로 계산된다.

## 컨트롤러 규칙

- 신호 전에도 탭을 받는다 — 성급하게 당기는 것도 플레이의 일부고 부정출발 판정은 서버
  몫이다. 눌러도 아무 일 없는 버튼은 "안 눌린 것"과 구별되지 않는다.
- 기록(ms) 자리는 항상 예약(`min-h-4`) — 뜰 때마다 위 칸이 밀리면 눈이 못 따라간다.
- 전송 실패 시 로컬 총알을 되돌린다 — 못 보냈으면 쏘지 않은 것이다.

## 사용법(`DuelHowTo`)이 연습을 강제하는 이유

신호는 1.4~4.6초 뒤 예고 없이 온다. 처음 휘두르는 사람은 감지 세기를 못 맞춰 첫 라운드를
통째로 날린다 — 대기실에서 한 번 성공해 두면 팔이 그 세기를 기억한다. 그래서 연습은
게임과 **같은 임계값**을 쓴다.
