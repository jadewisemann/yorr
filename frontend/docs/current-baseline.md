# 현재 적용 기준

> 기준일: 2026-07-27

이 문서는 각 주제의 **가장 최신판만** 반영한다. 이전 버전은 현재 구현 근거로 사용하지 않는다.

## 제품 범위

- 모바일 웹 기반 센서 요트다이스 게임
- MVP는 온라인 프라이빗 룸 모드만 제공
- 2~6인 실시간 멀티플레이
- 갤럭시 Chrome과 iPhone Safari 지원
- 링크·QR을 통한 빠른 입장
- 계정 없이 닉네임으로 참가
- 센서 실패·권한 거부 시 탭 조작으로 완주 가능
- 1판 약 4~5분을 목표로 동시 라운드와 타이머 사용

온라인 프라이빗 룸에서는 모든 참가자가 각자의 기기로 같은 게임 화면을 사용한다. 방 생성자는
대기실에서 게임을 시작할 권한만 가지며, 별도의 호스트 대시보드나 참가자 컨트롤러 화면으로
분리하지 않는다. 파티 모드와 빠른 대전은 MVP 범위에서 제외한다.

MVP 제외 항목은 AI 봇·AI 찾기, 창작 룰, 캐릭터/BGM, NFC, 커뮤니티 "요르의 지하실", 시즌 랭킹이다.

## 프론트엔드 기술 기준

- React + Vite 모바일 웹
- HTTPS 필수
- 센서: `DeviceMotion` / `DeviceOrientation`
- Android: `navigator.vibrate` 사용 가능 시 진동 피드백
- iOS: 센서 권한은 사용자 제스처 안에서 `requestPermission()` 호출
- iOS 웹 진동 미지원은 효과음·화면 흔들림·플래시로 대체
- 고빈도 원시 센서값은 전송하지 않고, 로컬에서 제스처를 판정한 뒤 게임 이벤트만 전송

## 실시간 통신 결정

2026-07-20 팀 결정에 따라 MVP 게임 데이터는 WebRTC DataChannel이 아니라 WebSocket을 사용한다.

- 전송: WSS, 클라이언트 ↔ Spring 서버
- 서버가 방·라운드·점수 상태의 권위자(authoritative server)
- 채팅은 같은 WebSocket 채널의 P1 확장
- WebRTC는 develop 단계의 온라인 음성 기능으로 분리

기획서 v0.3의 WebRTC DataChannel 설명보다 날짜가 더 최근인 이 결정과 2026-07-21 API 명세가 우선한다.

## 핵심 화면·상태

1. 인앱 브라우저 감지 및 외부 브라우저 유도
2. 온라인 프라이빗 룸 생성 또는 코드/QR 참가
3. 게임 선택
4. 닉네임 입력
5. iOS 센서 권한 온보딩
6. 대기실 참가자 목록과 방장 시작
7. 동시 라운드, 타이머, 최대 3회 굴림, 킵, 카테고리 확정
8. 실시간 점수판
9. 최종 결과와 재대결
10. 연결 끊김 후 재접속과 상태 스냅샷 복구

## 프론트엔드 안전장치

- 센서 권한 거부·미지원·값 미수신: 탭-투-롤
- 던지기 제스처 미인식: 화면의 명시적 확정 버튼
- 무음·진동 미지원: 비주얼 피드백 유지
- 인앱 웹뷰 오탐: "그냥 진행" 제공
- 중복/역순 요청: `msgId`/`seq` 기반으로 서버 응답과 정합성 회복
- 서버 상태와 불일치: 서버 스냅샷을 기준으로 클라이언트 상태 교정

## 미확정 사항

- 방 코드 만료 시각과 진행 중 난입/관전 정책
- 최소 인원 미달 시 게임 중단 이벤트(`game.aborted` 등) 필요 여부
- 파티 모드와 빠른 대전은 MVP 제외
- 12개 정규 카테고리 유지가 기본이고 8개 초스피드 모드는 후속 검토
- 1기기 구성을 MVP 기본으로 권장
