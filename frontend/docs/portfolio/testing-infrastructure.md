## 설계 — mock 백엔드가 두 벌인 이유

프로덕션 빌드는 MSW가 컴파일 아웃된다. 그래서 검증 대상별로 페이크를 분리했다:

- **개발·단위 테스트(소스 실행)**: MSW + `FakeRealtimeClient` 시나리오
  (`success·delay·error·duplicate·out-of-order·reconnect` — 중복·역순 메시지 내성을
  테스트로 표현 가능)
- **E2E mock 단(프로덕션 빌드 실행)**: `page.routeWebSocket`으로 게임 서버를 직접
  흉내내는 `fakeGameServer`(실서버와 같은 join 흐름 + 테스트가 원하는 순간 push) +
  `page.route` REST mock
- 두 벌을 잇는 다리 `contract.ts` — `wsEvents.ts`의 수동 미러를 이름·형태 동일하게
  유지해 **계약이 바뀌면 테스트 인프라가 먼저 깨진다**

## E2E 2단 구성 (17스펙 × 4 프로젝트)

- **mock 단(13스펙)**: 서버 없이 UI 계약 검증 — 방 생성/참가, 로비 실시간, 게임 전체
  흐름, 관전자 뷰, 단절/재접속("토큰을 사용자 승인 전에 제시하지 않는다" 포함), 로그인
  왕복, **320px 강건성**(스크린샷 대신 기하로 가로 넘침을 숫자 판정 — 넘친 요소 이름까지
  짚는다).
- **실서버 단(4스펙)**: `E2E_TARGET=real` — globalSetup이 백엔드 미기동을 30개 타임아웃
  대신 원인+복구 명령 한 문장으로 즉시 실패시킨다. 방 일회용 격리 원칙. 실서버 실측으로
  계약 불일치(한글 닉네임 400, 중복 닉네임 200 허용)를 발견해 주석으로 남겼다.
- 프로젝트 4종에 각각 존재 이유를 문서화 — 특히 `mobile-320`(지원 하한이 검증 밖에
  있었다)과 iPhone SE 프로필 대신 Pixel 리사이즈를 쓴 이유(webkit 강제 프로필이 view
  transition 겹침에서 렌더러 사망 — 실패 3건의 원인 규명).
- 3D 물리는 reduced-motion 강제로 결정적 2D 폴백으로 바꿔 검증 — 물리 정착 시점에
  의존하지 않는다.

## 커버리지 정책 — "분모가 전부다"

- **전체 `src`를 분모에** — 테스트가 import한 파일만 세면 실행된 적 없는 소스가
  분모에서 빠져 수치가 안전망 크기를 말하지 않는다.
- **래칫**: 실측(st 96.33 / br 91.94 / fn 96.63 / ln 98.40)에서 소폭 여유를 둔 하한을
  CI가 강제 — 오르면 임계값도 올린다.
- 제외에는 전부 근거를 적었다. 백미는 `World.ts` — 렌더 루프가 실제 시간을 재서 부하에
  따라 분기 커버리지가 71~85%로 흔들리는 유일한 파일임을 **동일 테스트 2회 실행
  비교(90.48% vs 91.43%)로 측정**해 제외하고, 근본 해법(시간 주입)까지 명시했다.
  테스트 47개는 그대로 돈다 — 빠지는 것은 측정뿐.

## flake — 우회가 아니라 근본 원인 제거

- jsdom에 WAAPI가 없어 `AnimatePresence` 퇴장이 안 끝난다 → "닫혔는가"를 검증 불가.
  motion을 통과 컴포넌트로 mock하고 `initial={false}` 강제 — 마운트 프레임 opacity:0이
  부하 걸린 CI에서만 터지는 flake의 **틈 자체를 없앴다**. Proxy 키 캐시로 매 렌더 타입
  변경(3D 재마운트)까지 차단.
- CI 러너가 로컬의 30배 느린 것을 측정해 `asyncUtilTimeout`/`testTimeout`을 조정하되,
  "대기 시간은 실패할 때만 소진된다"는 원리로 통과 경로를 느리게 만들지 않았다.
- fake timer + MSW 실타이머 혼합이 스위트를 불안정하게 만든 것을 확인하고 폴링 주기
  주입으로 우회 — flake 수정 이력이 전부 원인 분석과 함께 남아 있다.

## 그 외 품질 장치

`npm run check:cycles`(dpdm)로 도메인 단방향 의존을 CI에서 강제 · TypeScript strict +
`noUncheckedIndexedAccess`/`exactOptionalPropertyTypes` · jsdom용 WebGL 렌더러 대역
(`FakeWebGLRenderer`)으로 물리 코드까지 단위 테스트.

## 활용 포인트

  비교로 특정해 제외 근거를 문서화 — CI 랜덤 실패 0"
- "flake를 재시도로 덮지 않고 WAAPI 부재·CI 부하 배율 같은 근본 원인을 측정해 제거"
