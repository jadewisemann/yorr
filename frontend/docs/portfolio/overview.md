## 제품이 풀어야 했던 문제

- **입력이 특이하다**: 마우스 클릭이 아니라 휴대폰 모션 센서(흔들기·스윙)가 1급 입력이다.
  iOS/Android 센서 권한·이벤트 편차를 흡수하고, 센서가 없어도 탭으로 끝까지 플레이돼야 한다.
- **실시간 멀티플레이**: 서버가 방·게임 상태의 최종 권위자이고, 클라이언트는 WebSocket
  이벤트와 재접속 스냅샷으로 동기화한다. 모바일 브라우저는 백그라운드 전환·잠금으로
  수시로 연결이 끊기므로 복구가 핵심 품질이다.
- **3D 연출**: 주사위는 Three.js + Rapier 물리로 실제로 구르되, 결과는 서버가 정한 값과
  일치해야 한다.

## 기술 스택 (본인이 실제로 다룬 것)

| 영역 | 기술 |
|---|---|
| 앱 | React 19, TypeScript, Vite, TanStack Router, Zustand |
| 3D/물리 | Three.js, Rapier(@dimforge/rapier3d-compat, WASM), 결정론적 시뮬레이션 |
| 실시간 | WebSocket (FE/BE 공유 wire contract), 세션 FSM, heartbeat |
| UI | Tailwind CSS 4 semantic token 디자인 시스템, Motion, Popover/바텀시트 프리미티브 |
| 테스트 | Vitest + Testing Library(커버리지 v8), Playwright 2단 E2E(mock/실서버), MSW |
| 품질 도구 | Biome, CI flake 제거, 커버리지 리포트 연계 |
| 백엔드(교차) | Java 21 / Spring Boot — 판정 로직·스케줄러 버그 수정, 세션 복구 서버 측 구현 |
