# 3D 주사위 물리 — 던지기→예측→리맵→재생 파이프라인

> SSOT: [`../../src/yacht/rendering/physics-dice/`](../../src/yacht/rendering/physics-dice/) —
> `World.ts`(오케스트레이터) · `remap.ts`(예측·리맵) · `config.ts`(모든 상수) · `safety.ts`(봉쇄)

## 문제 정의

주사위 값은 서버 권위인데 연출은 진짜 물리여야 한다. 물리로 실제로 굴리면 멈춘 면이
서버 값과 다르고, 미리 만든 애니메이션은 흔들기 세기·던지는 각도를 반영하지 못한다.

## 굴림 3단계 모델 (`config.ts`)

1. **흔들기** — 사발 콜라이더 위를 **보이지 않는 뚜껑(lid)** 으로 막는다. 뚜껑이 있으니
   흔들림 임펄스를 세게 줘도 주사위가 튀어나오지 않고 사발 안에서 격렬하게 튄다.
   모션 모드에서는 기기 흔들림 펄스가 사발 진동의 유일한 에너지원이다 — 펄스가 끊기면
   지수 감쇠로 저절로 잦아든다.
2. **던지기** — 기울기 진행 0.55에서 주사위에 측면·상향 속도와 토크를 주고 사발 물리
   바디를 치운다. 이후 사발은 순수 비주얼이다 (예측 복제 시뮬과의 결정론 조건이기도 하다).
3. **비행·착지** — 고정 스텝 + CCD로 관통을 막고, 퍼져 구른 뒤 안착한다.

## 물리 닮음(dynamic similarity) — 낙하 속도 튜닝의 핵심

축척이 실물의 약 47배라 원래 튜닝은 1/15 슬로모션이었다. **중력만 올리면 안 된다** —
올바른 방법은 `GRAVITY_SCALE = 0.64`, `SPEEDUP = √0.64` 하나의 노브에서 전부 유도하는 것:
속도·각속도·임펄스 ×SPEEDUP / 감쇠·정착 임계 속도 ×SPEEDUP / 시간 ÷SPEEDUP /
거리·마찰·반발은 그대로. 이 관계가 깨지면 궤적의 **모양**이 바뀐다 — 중력만 12배 올렸을 때
비행 중 회전이 반토막 나 "주사위가 안 구르고 처박히는" 실측 사례가 근거다.

**480Hz 시뮬레이션**: 60Hz·중력 30에서는 한 스텝에 몸통의 53%를 지나가 주사위끼리 57%까지
파고들었다("겹침" 버그). 480Hz + Rapier soft CCD(0.15)로 관통이 0.284 → 0.073으로 줄었다.
반발은 `RestitutionCombineRule.Max` — 트레이 바닥과의 평균으로 깎이지 않아 눈에 보이는
튕김이 산다.

## 예측 → 리맵 → 재생 (`remap.ts` · `World.ts`)

```text
쏟는 순간(release)
  → planDiceTrajectory: 월드 스냅샷을 복제해 한 프레임 안에서 동기로 끝까지 시뮬
     - 자연 착지 눈(naturalDice) + 60fps 포즈 궤적(frames)을 함께 얻는다
     - 최대 3회 재시도(시드 결정론적 섭동), 겹침·엣지 스탠딩 점수로 최선의 궤적 선택
     - 서 있는 주사위는 최대 2회 floor assist로 눌러 앉힌다
  → cubeAlignmentOffset(target, natural): 목표면 법선→자연면 법선의 큐브 대칭 회전(90°/180°)
     mesh.quaternion = body.rotation × offset — 물리는 자연면으로 멈추고 화면에는 서버 값이 위
  → 바디를 Fixed로 전환, 궤적을 lerp/slerp로 재생만 한다
  → 정렬 단계: 서버 값 그대로 결과 줄/킵 레일에 정렬, onRollComplete(requestId, 서버값)
```

핵심 결정들:

- **두 번째 시뮬레이션을 만들지 않는다.** 예측용 월드와 화면용 월드를 따로 굴리면 작은
  충돌 오차가 카오스적으로 증폭되어 다른 착지 면이 나온다 — 예측한 궤적을 그대로 재생한다.
- **예측 상한 = 제품의 강제 종료 시간**(`maxRollDurationMs` ≈ 4.5초). 예측은 한 프레임에서
  동기로 돌므로 상한이 곧 최악의 프레임 지연이다. 상한에 걸려도 마지막 자세까지 궤적에
  포함해 예측/재생 불일치를 차단한다.
- **정착 판정은 스텝이 아니라 시간 기준**(0.12초 정지) — `simulationHz`를 바꿔도 의미가
  유지된다. `isBodySettled`는 예측 복제 시뮬과 실제 진행이 같은 기준을 쓰도록 한 곳에만
  정의한다.
- **결정론의 원천은 시드다** (`animationSeedForRoll` — 방·플레이어·라운드·굴림수·주사위의
  FNV-1a). 굴린 사람과 관전자 전원이 같은 스폰 지터·흔들림 노이즈·재시도 섭동을 얻는다.
  `random.ts`는 `domain/dice.ts`와 같은 LCG.
- **안전망** (`safety.ts`): 흔들기 중 매 스텝 `containDiceInBowl`(반경·바닥·뚜껑 클램프),
  비행 중 `containDiceInTray`(트레이 벽 반사, `enteredTray` 래치로 진입 중인 주사위는
  되튕기지 않음). 복제 시뮬에도 같은 보정을 적용한다 — 그래야 예측과 재생이 같다.
- 궤적 프레임의 수직 속도 변화에서 낙하/바운드를 감지해 `onDiceImpact`로 타격음을 낸다.
- 굴림이 영영 안 멈추는 경우에도 상한에서 조기 마감한다 — 결과값은 `targetDice`로 이미
  확정되어 있어 점수가 바뀌지 않는다.

## React 경계 (`PhysicsDiceScene.tsx`)

- World 모듈은 동적 import(`loadPhysicsDiceWorld`) — 로비에서 `prefetch`를 걸어 게임 진입
  시 로딩을 숨긴다 (`prefers-reduced-motion`에서는 걸지 않는다).
- reduced-motion·WebGL 실패 시 `PhysicsDiceFallback`(2D)으로 강등 — 이 폴백이 파티
  컨트롤러의 주 조작면으로 재사용된다. E2E도 reduced-motion을 강제해 결정적 검증을 한다.
- requestId 단위 멱등 집합 3개(`started`·`released`·`completed`)로 재렌더·중복 신호에
  안전하다. 모듈 로딩 중 도착한 props는 로드 후 재적용된다.
- 120px 이하의 컨테이너 크기 변화는 "3D 조정 중" 멈춤 없이 즉시 반영 — 배너·힌트 등장이
  만드는 수십 px 변화까지 매번 멈추면 게임이 자꾸 끊긴다.

## 카메라·배치

- 직교 카메라 탑다운. 흔들기 중에는 `simulationHalfWidth`로 넓히고 정렬 후 결과 폭으로
  복귀(900ms). 세로로 긴 화면에서는 빈 바닥 대신 좌우 가장자리를 잘라 주사위를 크게 보여준다.
- 배치 규칙(`layout.ts`)은 한 곳에만 — 즉시 배치·킵 토글 전환·굴림 후 정렬 세 경로가 같은
  규칙을 쓴다. `keepAll`(마지막 굴림)이면 다섯 개 전부 킵 레일로 — "더 굴릴 것이 없다"를
  자리로 말한다. 이미 킵된 주사위는 자기 슬롯을 지킨다 — 전부 재정렬하면 "확정"이 아니라
  "재배치"로 읽힌다.
