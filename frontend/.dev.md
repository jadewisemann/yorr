## ⚠️ 먼저 — 초기 진단 2건이 틀렸다

이 티켓 초반에 아래를 근본 원인으로 단정했는데 **둘 다 사실이 아니다.** 티켓 본문에도 정정을
남겼다. 옛 진단을 근거로 읽으면 안 된다.

| 틀린 주장 | 실제 |
|---|---|
| `break-keep` 사용 0건 — 한글 어절 보호가 없다 | `global.css`가 `:root`에 `word-break: keep-all` + `overflow-wrap: break-word`를 **이미 전역 적용** |
| `text-wrap: balance`가 `h3`에만 걸려 `h1`·`h2` 39곳이 무방비 | `h1, h2, h3` **전부**에 걸려 있다 |

원인은 두 가지다. `sed -n '28,50p'`로 `global.css`를 중간부터 읽어 26–27행의 `h1,` `h2,`를
놓쳤고, `break-keep`을 Tailwind **유틸리티만** grep해서 `@layer base`를 확인하지 않았다.

**교훈**: 「저장소에 X가 없다」를 유틸리티 grep만으로 결론 내리지 않는다. Tailwind 프로젝트는
같은 선언이 base 레이어에 있을 수 있다.

또 하나 — 계산된 스타일을 읽어 「셰브론이 회전하지 않는다」고 진단했는데 **이것도 틀렸다.**
브라우저 창이 표시되지 않으면 `document.visibilityState === 'hidden'`,
`document.timeline.currentTime === 0`이라 **애니메이션 타임라인이 진행하지 않는다.** 진행 중인
트랜지션의 시작값을 최종값으로 오해했다. 근거 없는 주석과 함께 넣은 코드는 되돌렸다.

**교훈**: 헤드리스/숨겨진 창에서 트랜지션·애니메이션에 의존하는 계산값은 신뢰할 수 없다.
최종값을 봐야 하면 `style.transitionProperty = 'none'`으로 끄고 읽는다. 정적 스타일(색·크기·
stroke)은 유효하다.

## A. 좁은 폭 강건성

### [x] A-1. 320px 검증 수단 확보

**현재 상태.** `global.css`가 `html`·`body`에 `min-width: 320px`으로 지원 하한을 선언했는데
`playwright.config.ts`의 모바일 프로젝트는 Pixel 7(412px)·iPhone 15(393px) 둘뿐이다.
**가장 잘 깨지는 폭이 검증 밖**이라 코드가 아니라 실기기에서 먼저 발견됐다.

**어떻게.** `mobile-320` 프로젝트(320×568)와 `e2e/mock/narrow-width.spec.ts` 신설.

```bash
npx playwright test --project=mobile-320 narrow-width
```

**스크린샷이 아니라 기하로 판정한다.** 스크린샷 비교는 폰트 렌더 차이로 흔들리고 무엇이
틀렸는지 말해 주지 않는다. 가로 넘침은 숫자로 판정되고 넘친 요소의 이름까지 짚을 수 있다.

검사 3종:

- `expectNoHorizontalOverflow` — 감춰 주는 조상이 없는데도 뷰포트를 넘는 요소
- `expectKoreanWordBreakProtected` — 전역 `keep-all`이 실제 텍스트까지 닿는지
- `labelFit` — 짧은 라벨이 **제 칸 안에 한 줄로** 들어가는지

**손대는 곳**: `playwright.config.ts`, `e2e/mock/narrow-width.spec.ts`(신설)

#### 이 스펙을 손댈 때 지킬 것

세 가지를 의식적으로 넣었으니 지워지지 않게 한다.

1. **헛도는 단정을 만들지 않는다.** 한글 검사에 `examined > 0` 가드가 있다. 대상이 0개면
   통과가 안전을 뜻하지 않으므로 그 사실 자체를 실패로 만든다.
2. **단정이 실제로 회귀를 잡는지 확인한다.** 태그라인·라운드 라벨 단정은 수정을 떼어 실패하는
   것을 확인했다. `labelFit`은 처음에 줄 수만 셌는데 **수정을 떼도 통과했다** — `nowrap`만
   걸어도 줄 수는 1이 되고, 대신 라벨이 칸을 삐져나와 옆 버튼과 겹치며 그 겹침은 뷰포트
   안이라 넘침 검사에도 안 걸린다. `scrollWidth`와 부모 경계를 함께 봐야 잡힌다.
3. **덮지 못한 것은 이유를 적어 비워 둔다.** 통과하는 스펙으로 위장하지 않는다.

### [x] A-2. 나란히 선 요소가 텍스트를 압착해 줄이 두 배로 늘던 것

**현재 상태.** 브라우저에서 393px과 320px의 렌더된 **줄 수**를 비교해 찾았다. 원인은 줄바꿈
속성이 아니라 flex 행에서 `shrink-0` 형제가 텍스트 칸을 압착하는 것이다.

| 요소 | 받는 폭 | 결과 |
|---|---|---|
| 랜딩 태그라인 `h1` | 320 − 40(padding) − 12(gap) − **116(초대 코드 칩 `shrink-0`)** = **152px** | 24px 글자로 **4줄 · 120px** |
| 캐러셀 스와이프 힌트 | 280 − 55(카운터) − 102(tablist) − 24(gap) = **99px** | **2줄 · 36px** |

태그라인은 세로 한 층을 아끼려고 초대 코드 옆에 붙인 것인데, **그 층보다 큰 높이를
태그라인에서 되돌려 받고 있었다.**

**어떻게.** `--breakpoint-tiny: 22.5rem`(360px)을 토큰에 두고 **하한 전용** `max-tiny:`로 쓴다.

- 태그라인: 360px 미만에서 쌓아 280px을 받게 → 4줄 → **2줄**(120 → 60px). 행 높이도
  131 → **125px로 오히려 감소**
- 힌트: 그 폭에서 감춘다 — 오른쪽 정렬 2줄은 안내가 아니라 깨진 것으로 읽힌다. 스와이프는
  카드로 발견되고 위치는 tablist가 계속 말한다
- 360px 이상 배치는 그대로(393px에서 `flex-direction: row` · h1 2줄 유지 확인)

**손대는 곳**: `src/styles/tokens.css`, `src/landing/screens/EntryPage.tsx`,
`src/landing/components/LandingProgress.tsx`

### [x] A-3. 게임 헤더 라운드 라벨이 접히던 것

**현재 상태.** 320px 헤더는 고정 요소가 폭을 다 먹는다 — 나가기 44 + 도움말 44 + 소리 44 +
타이머 52 + 좌우 여백 32 + gap 60 = **276px**. `flex-1`인 턴 표시 칸에 **56px**만 남고
「Round 01 / 12」는 넓은 자간까지 합쳐 약 110px이라 두 줄로 접혔다.

**어떻게.** 그 폭에서는 `Round`와 넓은 자간을 뺀다. 숫자 쌍만 남아도 옆의 원형 타이머와
나란히 놓이면 라운드 진행으로 읽히고, 정확한 낭독은 sr-only `h1`이 이미 한다
(「요르 게임 진행 중 · N / 12 라운드」). `whitespace-nowrap`도 함께 걸어 폭이 더 줄어도
접히는 대신 잘리게 한다 — 접히면 헤더 안에서 줄 수가 흔들린다.

**정상 리플로는 건드리지 않았다.** 닉네임 제목이 2줄, 튜토리얼 안내문이 4줄이 되는 것은
좁아진 폭에 맞춰 접히는 것이고 `text-balance`가 이미 다룬다.

**손대는 곳**: `src/yacht/screens/GamePlayHeader.tsx`

### [x] A-4. 게임 화면 검증 공백 해소

**현재 상태.** 게임 화면은 좁은 폭에서 가장 붐비는데 스펙이 닿지 않았다.

**손대는 곳**: `e2e/mock/narrow-width.spec.ts`

### [x] B-1. 아이콘 역할 글리프 → 공용 SVG (12곳)

## C. 주간 랭킹 띠

### [x] C-1. 글로우·`will-change`·일시정지·빈 상태

**글로우 2개 제거.** `LandingProgress`가 이미 같은 판단을 적어 뒀다 — "화면에서 유일하게
빛나는 레드는 CTA여야 한다". 랭킹 띠는 랜딩 최상단이라 글로우를 두면 그 아래 CTA와 시선을
다툰다. 1위 배지는 배경색 반전으로 이미 구분되고, 라벨 점은 맥동(`ring-pulse`)이 살아 있음을
이미 말한다. 계산된 `box-shadow`가 둘 다 `none`인 것을 확인했다.

**`will-change`를 활성 애니메이션으로 좁힘.** `motion-reduce`에서는 애니메이션이 없는데
`will-change-transform`이 남아 레이어를 붙잡고 있었다 → `motion-safe:`로 좁힌다.
(`baseline-ui`: will-change는 활성 애니메이션 밖에서 쓰지 않는다)

**키보드·터치 일시정지.** `hover`만 있어 마우스 없는 환경에서는 흐르는 띠를 멈출 방법이
없었다 → `focus-within` 추가. (`fixing-accessibility`: hover 전용 인터랙션은 키보드 등가물
필요)

**빈 상태가 행동을 잃던 것.** narrow 뷰포트가 ~168px뿐이라 기존 문구("이번 주 기록이 아직
없어요 — 로그인하고 첫 순위의 주인이 되어보세요")가 `truncate`로 앞머리만 남고 **행동이
통째로 잘렸다.** 빈 상태에는 다음 행동이 하나 남아 있어야 하므로 "로그인하고 1위 도전하기"로
줄였다 — 기록이 없다는 사실은 이름이 하나도 없는 것으로 읽히고, 무엇의 순위인지는 왼쪽 고정
라벨이 말한다.

**손대는 곳**: `src/landing/components/RankingTicker.tsx`,
`src/landing/components/__tests__/RankingTicker.test.tsx`

## D. 이모지 리액션

### [x] D-1. 입력 — Tab으로 도달할 수 없었다

**현재 상태.** 픽커는 닫혔을 때 트리거를 아래로 밀지 않으려고 `absolute`로 띄웠고, 그 결과
DOM에서 트리거보다 **앞**에 있다. 열어도 Tab을 앞으로 눌러서는 칸에 닿을 수 없었다
(`fixing-accessibility`: 모든 인터랙티브 요소는 Tab으로 도달 가능해야 한다).

**어떻게.**

- 열면 첫 칸에 포커스. 그 뒤는 방향키가 옮긴다(`role="toolbar"`, 양 끝 wrap)
- 열려 있어도 Tab에 걸리는 칸은 현재 하나뿐(roving tabindex) — 다섯 칸이 각각 Tab을 먹으면
  헤더까지 다섯 번을 더 눌러야 한다
- Escape로 닫을 때 트리거로 포커스 복귀 — 사라진 요소에 포커스가 남으면 다음 Tab이 문서
  처음으로 튄다
- 바깥 누르면 닫힘 — 랜딩 랭킹 드롭다운과 같은 규칙(모달이 아니므로 뒤를 잠그지 않는다)
- **보낸 뒤에 닫지 않는다** — 리액션은 대화가 아니라 환호라서 연달아 누르는 것이 기본인데,
  매번 닫혀 세 번 보내려면 세 번 열어야 했다. "게임 화면을 계속 덮지 않는다"는 원래 의도는
  이제 바깥 누르기·Escape·트리거 재클릭이 받는다 — 그 전에는 자동 닫힘이 **유일한 수단**이라
  닫아야 했다

방향키 헬퍼는 `landing/tablistNavigation.ts` → **`shared/rovingFocus.ts`로 이동**
(`resolveTablistKey` → `resolveRovingKey`). 의존 방향이 `landing → room → yacht`라 야추가
랜딩을 import할 수 없고, 두 도메인이 함께 쓰는 순수 함수는 경계 모듈 `shared`의 몫이다.
새 구현을 만들지 않았다.

**손대는 곳**: `src/shared/rovingFocus.ts`(이동), `src/shared/__tests__/rovingFocus.test.ts`,
`src/landing/components/LandingProgress.tsx`, `src/yacht/components/ReactionDock.tsx`,
`src/yacht/components/__tests__/ReactionDock.test.tsx`

### [x] D-2. 표시 — 동시 도착이 서로를 가렸다

**현재 상태.** 좌우(`--drift`)만 흔들어 같은 순간에 온 것들이 **같은 높이에 한 줄로**
올라갔고, `motion-reduce`에서는 제자리에 뜨므로 닉네임 필이 2.2초 동안 그대로 겹쳤다.
**파일 주석이 이미 알고 있던 결함**이고 "실제로 겹쳐서 못 읽겠다는 얘기가 나오면 그때 세로
오프셋을 추가한다"고 미뤄 둔 것이다.

**어떻게.** `--lift`로 도달 높이까지 항목마다 흔든다. keyframe은 `-8.5rem`에 `--lift`를
더하고, `motion-reduce`에서는 호출부의 `translate-y`가 그대로 적용돼 같은 값으로 세로
분산된다.

`LIFTS` 길이(3)를 `DRIFTS`(5)와 **서로소**로 뒀다. 같은 길이면 두 값이 같은 주기로 돌아
조합이 5가지뿐인데, 서로소면 15가지가 돌아간다 — `MAX_FLYING`(12)보다 크므로 **화면에 함께
떠 있는 것들끼리는 절대 같은 좌표를 쓰지 않는다.**

**손대는 곳**: `src/styles/tokens.css`(`@keyframes reaction-float`),
`src/yacht/components/ReactionDock.tsx`
