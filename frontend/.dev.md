# S15P11A406-18 참가자 로컬 게임 코어 구현 계획

> 작성일: 2026-07-27
> Jira: [S15P11A406-18](https://ssafy.atlassian.net/browse/S15P11A406-18)
> 작업 브랜치: `feature/18-local-game-core`
> 제품 기준: `docs/current-baseline.md`
> 규칙 기준: `docs/product/planning.md`
> 아키텍처 기준: `docs/engineering/architecture-and-stack.md`
> WebSocket SSOT: `src/realtime/wsEvents.ts`

## 목표

한 참가자의 굴림, KEEP, 카테고리 선택, 점수 제출 상태를 부작용 없는 순수
TypeScript 도메인으로 구현한다. 같은 seed와 같은 상태는 같은 결과를 만들고, 이후
서버가 주사위 결과의 권위자가 되어도 UI와 렌더러가 사용하는 계약은 유지한다.

기존 `.dev.md`의 온라인 프라이빗 룸 기준과 `S15P11A406-72` 완료 조건은 이미
`develop`에 반영됐고 `docs/current-baseline.md`에서 관리되므로 이 계획에서 제거한다.

## 기준과 경계

- 주사위는 항상 5개이며 각 눈은 `1`부터 `6`까지다.
- 정규 카테고리는 `ones`, `twos`, `threes`, `fours`, `fives`, `sixes`,
  `choice`, `fourOfAKind`, `fullHouse`, `smallStraight`, `largeStraight`,
  `yacht`의 12개다.
- 상단 소계가 63점 이상이면 35점 보너스를 적용한다.
- 현재 티켓에서는 로컬 코어가 seed로 다음 주사위를 계획한다. 방, 라운드, 최종
  점수의 권위가 서버에 있다는 제품 원칙은 바꾸지 않는다.
- 계획된 주사위는 굴림 완료 전 현재 주사위로 공개하지 않는다. 렌더러에는
  `requestId`, `seed`, `targetDice`, `held`만 전달하고 완료 이벤트로 상태를 확정한다.
- `src/domain/`은 React, DOM, Three.js, Rapier, Zustand, REST, WebSocket을
  import하지 않는다.
- `wsEvents.ts`는 이벤트와 payload의 SSOT로 유지한다. 공용 주사위·카테고리 타입이
  필요하면 의존 방향을 `realtime → domain`으로 두고 기존 export 이름을 보존한다.
- 새 런타임 의존성은 추가하지 않는다.

## 구현 전 코드 상태

- `src/domain/`과 `yachtGame` 단위 테스트가 없다.
- `src/realtime/wsEvents.ts`에는 카테고리와 보너스 상수가 있으나 `DiceSet`이
  가변 길이 배열이라 5개 제약을 표현하지 못한다.
- `Dice`, `ScoreRow`는 표현 컴포넌트만 제공하며 게임 규칙과 상태 전이는 없다.
- `RollIntent`는 입력 의도만 표현하므로 센서·탭 입력 통합은 이 티켓 범위가 아니다.

## 파일별 구현

### `src/domain/dice.ts`

- `DiceValue`와 길이 5의 readonly `DiceSet`을 정의한다.
- 외부 값이 정확히 주사위 5개인지 검사하는 타입 가드 또는 생성 함수를 제공한다.
- KEEP 상태도 길이 5의 불리언 튜플로 표현한다.
- seed를 직접 변경하지 않는 결정적 난수 함수를 구현한다.
- 이전 주사위와 KEEP을 받아 KEEP되지 않은 위치만 다시 굴린다.
- 굴림 계획 결과는 `requestId`, 입력 seed, 다음 seed, `targetDice`, `held`를
  포함한다. 같은 입력은 항상 같은 계획을 반환한다.

### `src/domain/scoring.ts`

- 12개 카테고리와 상단 카테고리, 보너스 상수를 순수 도메인 계약으로 정의한다.
- 카테고리별 예상 점수를 계산한다.
  - 상단: 해당 눈의 합
  - choice: 전체 합
  - four of a kind: 같은 눈이 4개 이상이면 전체 합, 아니면 0
  - full house: 2개와 3개 조합이면 전체 합, 아니면 0
  - small straight: 서로 다른 연속 4개가 있으면 15점
  - large straight: 서로 다른 연속 5개면 30점
  - yacht: 같은 눈 5개면 50점
- 사용한 카테고리를 제외한 후보 점수를 계산한다.
- 카테고리별 확정 점수에서 상단 소계, 보너스, 하단 합, 총점을 파생한다.
- 0점으로 카테고리를 포기해도 해당 카테고리는 사용 완료로 취급한다.

### `src/domain/yachtGame.ts`

- 한 참가자의 로컬 상태를 다음 단계로 명시한다.
  - `ready`: 굴림 가능
  - `rolling`: 렌더러 완료 대기
  - `choosing`: KEEP 또는 카테고리 선택 가능
  - `submitting`: 제출 결과 대기
  - `roundComplete`: 현재 라운드 제출 완료
- 상태에는 현재 주사위, KEEP, 굴림 횟수, 사용한 카테고리와 점수,
  선택 카테고리, 처리 중인 굴림 계획을 둔다.
- 순수 reducer action으로 아래 전이를 구현한다.
  - 굴림 요청과 렌더러 완료
  - KEEP 토글
  - 카테고리 선택
  - 제출 시작, 성공, 실패
  - 다음 라운드 시작
- 첫 굴림 전 KEEP, 네 번째 굴림, 사용한 카테고리 선택을 거부한다.
- `rolling` 중 추가 굴림과 `submitting` 중 추가 제출은 상태를 바꾸지 않는다.
- 굴림 완료 action의 `requestId`가 현재 계획과 다르면 오래된 완료로 보고 무시한다.
- 세 번째 굴림 뒤에는 KEEP 변경과 추가 굴림을 막고 카테고리 선택만 허용한다.
- reducer는 비동기 호출을 수행하지 않고 제출 payload와 렌더러 명령에 필요한
  데이터만 파생할 수 있게 한다.

### `src/realtime/wsEvents.ts`

- 도메인에서 확정한 `DiceValue`, `DiceSet`, 카테고리와 보너스 계약을 import해
  기존 WebSocket export 이름을 유지한다.
- 이벤트 이름과 payload 구조는 변경하지 않는다.
- API와 mock의 기존 import가 깨지지 않는지 타입 검사로 확인한다.

### `src/domain/*.test.ts`

주사위, 점수, 상태 전이 테스트를 각 구현 파일과 나란히 두고
`npm test -- src/domain` 한 명령으로 순수 도메인 회귀를 검증한다.

- 같은 seed와 상태의 결정성, 다른 seed의 독립성
- KEEP 위치 유지와 나머지 위치 재굴림
- 주사위 개수와 눈 범위 검증
- 첫 굴림 전 KEEP 거부, 최대 3회 굴림
- 12개 카테고리의 성공·실패·경계 점수
- small straight의 중복 눈 처리와 두 연속 패턴
- 상단 62/63점 보너스 경계와 총점
- 사용한 카테고리 재선택 및 0점 포기 처리
- 굴림·제출 처리 중 중복 action 차단
- 오래된 `requestId` 완료 무시
- 굴림 완료 전 `targetDice`가 현재 주사위에 반영되지 않음

## 구현 순서

1. `dice.ts`의 고정 길이 타입, 검증, seed 굴림과 굴림 계획 계약을 만든다.
2. `scoring.ts`의 12개 점수 규칙, 후보, 보너스와 합계를 만든다.
3. `yachtGame.ts`의 상태와 reducer 전이를 만든다.
4. `wsEvents.ts`가 도메인 원시 계약을 재사용하도록 연결한다.
5. 각 도메인 테스트에 완료 조건과 경계 사례를 작성한다.
6. `npm run typecheck`와 `npm test -- src/domain`을 실행한다.
