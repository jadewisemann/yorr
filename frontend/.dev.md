## 1. 현재 상태 진단

| 항목 | 현재 | 문제 |
|---|---|---|
| E2E 실행 대상 | `vite preview`(포트 4306) + 프로덕션 빌드 | MSW는 `import.meta.env.DEV`에서만 켜짐 → 빌드 결과물은 목도 실서버도 없이 API가 전부 실패하는 상태로 랜딩 화면만 검증 |

## 2. 목표

1. 로컬에서 실제 백엔드(Spring Boot, `backend/`)를 띄우고 프론트가 그 서버를 바라보는
   **real-server 실행 모드**를 만든다.
2. 그 모드 위에서 도는 **광범위한 Playwright E2E 스위트**를 추가한다
   (기존 MSW-독립 스모크는 유지).
3. **테스트 커버리지 리포트/임계값**을 셋업하고 현재 수치를 기록한다.
4. **순환 복잡도(cyclomatic/cognitive complexity)와 순환 참조(circular import) 지표**를
   측정해 리팩토링 대상을 선정하고, 리팩토링 전에 그 대상을 고정하는
   **특성화(characterization) 테스트**를 셋업한다.

리팩토링 자체는 이 티켓 범위가 아니다. 이 티켓은 "리팩토링을 안전하게 시작할 수 있는
테스트 기반"까지만 만든다.

## 3. 단계별 계획

### 3.1 실제 서버 경로 추가 (개발 환경)

**백엔드 실행 (수정 없이 사용만):**

```bash
cd backend && docker compose up -d   # 의존 인프라(DB 등)
./gradlew bootRun                    # localhost:8080
```

**프론트 변경:**

- `vite.config.ts`에 dev/preview 공용 proxy 추가:
  - `/api` → `http://localhost:8080` (REST)
  - `/ws` → `ws://localhost:8080` (`ws: true`, WebSocket)
  - 대상 주소는 `VITE_BACKEND_ORIGIN` 환경변수로 오버라이드 가능하게 한다
    (기본 `http://localhost:8080`)
- `.env.example`에 실서버 모드 예시 추가:

  ```bash
  # 실서버 모드: MSW 끄고 proxy로 백엔드 직결
  VITE_ENABLE_MSW=false
  VITE_BACKEND_ORIGIN=http://localhost:8080
  VITE_WS_URL=/ws/v1/game   # 상대경로면 same-origin proxy를 타도록 realtimeClient 확인
  ```

- `realtimeClient.ts`가 절대 `ws://` URL만 받는다면 상대경로(`/ws/...`)를
  `location.origin` 기준으로 해석하는 분기를 추가한다 (이 티켓에서 유일한 src 코드 변경).
- `package.json` 스크립트 추가:
  - `dev:real` — `VITE_ENABLE_MSW=false vite` (cross-env 필요 시 devDependency 추가)

**완료 조건:** MSW 끈 상태로 `npm run dev:real` → 브라우저에서 방 생성이 실제 백엔드
응답으로 성공한다.

### 3.2 E2E 하네스 이원화 (mock / real)

Playwright 설정을 **두 개의 실행 모드**로 나눈다. 기존 스펙은 그대로 mock 모드에 남긴다.

```
e2e/
  mock/          # 기존 smoke.spec.ts, landing.spec.ts 이동 — 서버 없이 UI 계약만
  real/          # 신규 — 실제 백엔드 필수
  support/       # 공용 헬퍼 (방 생성, 참가, 셀렉터 상수)
  preview-server.mjs
```

- `playwright.config.ts`:
  - `E2E_TARGET=real`일 때 `testDir: e2e/real`, webServer가 proxy 켜진 preview
    (또는 dev 서버)를 실행, `VITE_ENABLE_MSW=false`
  - 기본(mock)일 때 현재와 동일
  - real 모드 시작 전 `http://localhost:8080` health check로 백엔드 미기동이면
    명확한 에러 메시지로 즉시 실패시킨다 (globalSetup)
- 프로젝트(브라우저) 매트릭스는 현행 유지: mobile-chrome · mobile-safari · desktop-chrome
- `package.json` 스크립트:
  - `test:e2e` — 기존 (mock)
  - `test:e2e:real` — `E2E_TARGET=real playwright test`

**real 모드 격리 원칙:**

- 각 테스트가 자기 방을 새로 만들고 그 방 코드로만 상호작용한다 (전역 상태 공유 금지)
- 서버 데이터를 직접 정리하는 API가 없으므로 "방은 일회용"으로 취급한다
- 다중 사용자 시나리오는 `browser.newContext()` 2개(호스트/게스트)로 구성한다

### 3.3 광범위한 E2E 시나리오 (real 모드)

우선순위 순. 각 스펙은 실서버 상태 전이를 검증한다.

| # | 스펙 | 시나리오 |
|---|---|---|
| 1 | `room-create.spec.ts` | 방 만들기 → 방 코드·QR 표시 → 로비 진입 |
| 2 | `room-join.spec.ts` | 게스트가 초대 코드로 참가 → 닉네임 입력 → 양쪽 로비에 두 플레이어 표시 (2 context) |
| 3 | `room-join-errors.spec.ts` | 존재하지 않는 코드, 정원 초과, 중복 닉네임 등 서버가 실제로 반환하는 에러 UX |
| 4 | `game-start.spec.ts` | 호스트 시작 → 양쪽 모두 게임 화면 전환, 턴 순서 일치 |
| 5 | `game-roll-score.spec.ts` | 탭 굴림 → 서버 브로드캐스트 주사위 값 양쪽 일치 → KEEP → 점수 기록 → 턴 넘어감 |
| 6 | `game-full-round.spec.ts` | 한 게임 완주(카테고리 자동 선택 헬퍼) → 결과 화면 순위 표시 |
| 7 | `reconnect.spec.ts` | 게임 중 `page.reload()` → 스냅숏 복원으로 동일 상태 복귀 |
| 8 | `turn-timer.spec.ts` | 턴 타이머 만료 시 서버 강제 진행 반영 (최근 fix/96 회귀 방지) |

작성 규칙:

- 셀렉터는 role/label 우선 (기존 스펙 스타일 유지), 불가할 때만 `data-testid` 추가
- 3D 물리 연출은 완료 이벤트/DOM 상태로 대기하고, 애니메이션 자체는 검증하지 않는다
- 고정 `waitForTimeout` 금지 — 서버 이벤트로 인한 DOM 변화를 `expect().toBeVisible()`
  폴링으로 기다린다
- WebSocket 지연을 감안해 real 모드 `expect.timeout`을 별도 상향 (예: 10s)

### 3.4 커버리지 셋업

- `package.json`: `test:coverage` — `vitest run --coverage`
- `vitest.config.ts` coverage 설정 보강:
  - `reporter: ['text', 'html', 'lcov', 'json-summary']` (CI·후속 도구 연계용)
  - `include: ['src/**']`, 제외: `src/mocks/**`, `src/test/**`, `*.test.*`,
    `src/vite-env.d.ts`, `src/main.tsx`
  - 3D 렌더링(`src/rendering/**`)은 jsdom에서 의미 있는 커버리지가 안 나오므로
    측정은 하되 임계값 산정 근거에서 분리해 기록한다
- **임계값은 "현재 측정값 - 소폭 여유"로 시작**한다 (ratchet 방식). 도달 불가능한 80%
  같은 값을 걸어 CI를 즉시 깨뜨리지 않는다. 첫 측정 후 `thresholds`를 커밋에 포함한다.
- 측정 결과(전체/레이어별 %)를 이 문서 하단 "측정 기록" 절에 追記한다.

### 3.5 복잡도·순환 참조 지표와 리팩토링용 테스트 셋업

**지표 측정 (devDependencies 추가):**

1. **순환 복잡도**: Biome `noExcessiveCognitiveComplexity` 룰을 `biome.json`에
   `"warn"`(초기)으로 추가해 인지 복잡도 상위 파일을 추출한다. 수치 기반 상세 랭킹이
   필요하면 일회성으로 `npx eslint --no-eslintrc --rule '{"complexity": ["warn", 10]}'`
   또는 `ts-complex` 계열 리포트를 사용하고, 도구를 영구 의존성으로 늘리지 않는다.
2. **순환 참조**: `madge --circular --extensions ts,tsx src/`를
   `check:cycles` 스크립트로 추가한다. 순환 0이면 그 상태를 게이트로 고정하고,
   존재하면 목록을 이 문서에 기록하고 게이트는 현재 개수 이하로 잠근다(ratchet).

**리팩토링 대상 선정 기준:** 복잡도 상위 + 커버리지 하위 + 순환 참조 연루 파일의 교집합.
현재 코드 기준 유력 후보(측정으로 확정): `src/screens/GamePage.tsx`,
`src/input/MotionGestureRecognizer.ts`, `src/rendering/physics-dice/*`,
`src/realtime/realtimeClient.ts`.

**특성화 테스트 셋업:** 선정된 각 대상에 대해, 리팩토링 전에 현재 동작을 고정하는
테스트를 추가한다.

- 순수 로직(도메인·인식기): 입력→출력 스냅숏이 아닌 **명시적 기대값** 단위 테스트
- 화면(GamePage 등): RTL로 사용자 시나리오 단위 (렌더링 확인용 테스트 금지 —
  frontend/CLAUDE.md 테스트 최소화 원칙 준수)
- 계약 경계(realtimeClient): FakeRealtimeClient와 실제 client가 같은 인터페이스
  계약을 지키는지 공용 계약 테스트

여기까지가 이 티켓의 끝이다. 실제 리팩토링은 별도 `refactor/*` 브랜치·티켓으로 진행한다.

## 6. 리스크 · 미해결 질문

- **백엔드 로컬 기동 조건**: `backend/compose.yaml` 의존 서비스와 필요 환경변수를
  실행 시점에 확인해야 한다. 기동 불가면 real E2E는 배포된 개발 서버 URL로
  `VITE_BACKEND_ORIGIN`을 돌려 대체한다 (이 경우 테스트 방 생성이 공용 서버에
  쌓이는 점을 팀에 공유).
- **테스트 데이터 잔류**: 서버에 방 삭제 API가 없으면 만든 방이 남는다. TTL 여부 확인.
- **mobile-safari(WebKit) 실서버 WS 안정성**: flaky하면 real 모드는 chromium 2종만
  우선 돌리고 WebKit은 스모크만 유지한다.
- **CI(Jenkinsfile) 통합**: real E2E를 CI에서 돌릴지(백엔드 컨테이너 기동 포함)는
  이 티켓 범위 밖 — 로컬 하네스까지만 완성하고 CI 연동은 후속 티켓 제안.
- **`.dev.md` 이력**: 이 파일의 이전 내용(모바일 센서 구현 계획, 티켓 98)은 병합 완료되어
  본 계획으로 교체함. 필요 시 git 이력에서 복원 가능.
