# .dev.md — 리팩토링 전 테스트 안전망 구축 기록

> 브랜치: `frontend/test/add-e2e-and-coverage` (base: `frontend/base` @ e634dc6)
> 목적: **리팩토링에 앞서** 다양한 시나리오의 E2E 테스트를 확보하고, vitest 커버리지를 90%
> 이상으로 끌어올려 회귀 안전망을 만든다. 이 브랜치는 소스 코드를 리팩토링하지 않는다 —
> 테스트와 테스트 설정만 추가한다.

## 설계

### 커버리지 기준부터 다시 잡았다

기존 `vitest.config.ts`에는 `coverage.include`가 없었다. 이 상태에서는 **테스트가 import한
파일만** 분모에 들어가고, 한 번도 실행되지 않은 파일은 통계에서 통째로 빠진다. MotionLab
계열(~1,000줄), `heroScene.ts`(478줄), `realtimeClient.ts`, `mocks/browser.ts` 같은 파일이
전부 빠진 채로 "66.75%"가 나오고 있었다 — 실제 안전망 크기를 과장하는 숫자였다.

`coverage.include: ['src/**/*.{ts,tsx}']`로 전체 소스를 분모에 넣고 다시 쟀더니 **49.96%**가
나왔다. 이 숫자를 정직한 베이스라인으로 삼았다.

제외한 것과 근거:

| 제외 대상 | 근거 |
|---|---|
| `src/main.tsx` | 부트스트랩. DOM 마운트 한 줄 — E2E가 사실상 검증 |
| `src/vite-env.d.ts` | 타입 선언 |
| `src/test/**` | 테스트 하네스 자체 |
| `src/app/DevCatalog.tsx` | `/__dev/components` — DEV 게이트 걸린 내부 컴포넌트 카탈로그 |
| `src/app/PhysicsDiceDemo.tsx` | 개발용 물리 주사위 데모 화면 |
| `src/app/MotionLab*.tsx` · `useMotionLab.ts` | `/__dev/motion` — 실기기 센서 튜닝용 내부 도구 UI. 리팩토링 대상인 제품 코드가 아님 |

MotionLab이라도 **순수 로직 파일**(`motionLabParams.ts` · `motionLabReplay.ts` ·
`motionLabClipboard.ts`)은 UI가 아니라서 분모에 남기고 테스트했다.

### 테스트 작성은 계층별로 나눠 병렬 진행했다

레이어 경계(`app → screens → components · api · realtime → store · cn`, 루트 CLAUDE.md
참고)를 그대로 작업 분할 기준으로 썼다:

1. **rendering** — `physics-dice/*`(World·model·layout·arena·appearance·diceInstances·
   interaction·safety·stage) + `rendering/hero/heroScene.ts` + `components/HeroCanvas.tsx`
2. **components** — 나머지 `src/components/*`
3. **screens·app** — `src/screens/*`, `src/app/*`(개발 전용 제외)
4. **api·mocks·realtime·유틸** — `src/api` · `src/realtime` · `src/core` · `src/mocks` ·
   `src/contracts` · `src/feedback` · `src/input` · `src/domain` · 루트 유틸(`nickname` ·
   `roomCode` · `store` · `roomSessionStorage` 등)
5. **E2E** — Playwright 시나리오 스위트

각 갈래에 공통으로 건 제약: **src 소스 수정 금지**(테스트 파일만 추가/확장), 파일별 라인
커버리지 90%+ 목표, 완료 조건은 `vitest` 통과 + `biome check` 이슈 0 + `tsc` 통과.

### 물리 렌더링 테스트: WebGLRenderer만 모킹하고 나머지는 실제로 구동

`PhysicsDiceWorld`(`World.ts`)는 Rapier 물리 연산 자체는 순수 JS/WASM이라 jsdom에서도 실제로
돌릴 수 있다. 막히는 지점은 `createStage()`가 만드는 `THREE.WebGLRenderer` 하나뿐이다.
`vi.mock('./stage')`로 fake renderer(scene·camera·조명 포함)만 주입하고 나머지(물리 스텝,
layout, settle 판정, startRoll/pour/syncCommittedDice/applyQuality/destroy, 콜백)는 전부
실제 코드로 검증했다. `heroScene.ts` · `stage.ts`도 같은 방식(`vi.mock('three', ...)`로
`WebGLRenderer`만 교체)으로 실제 THREE 장면 구성 코드를 그대로 검증했다.

### E2E: 프로덕션 빌드 기준으로 REST·WS를 둘 다 mock한다

`npm run test:e2e`가 띄우는 프리뷰 서버는 **프로덕션 빌드**를 서빙한다. 이 빌드에서는
MSW·mock WS가 전부 꺼진다(`resolveMswMode()`가 `!DEV`면 `'off'`). 그래서:

- **REST**는 Playwright `page.route()`로 `/api/v1/**` 응답을 만든다.
- **WebSocket**은 Playwright `page.routeWebSocket()`으로 `/ws/v1/game` 서버 역할을 직접
  흉내낸다(`sys.connected` 인사 → `room.join` 수신 → `room.joined` 응답, 이후 push는 테스트가
  원하는 순간에 직접 보낸다).
- 계약 SSOT(`src/realtime/wsEvents.ts`)는 `e2e/` 쪽에서 직접 import할 수 없다(e2e는
  tsconfig 밖이고 `@/` 별칭도 안 풀린다) — 그래서 `e2e/support/contract.ts`에 실제로 쓰는
  필드만 미러링해 뒀다. **이 미러가 원본과 어긋나면 감지할 방법이 없다** — 한계로 아래에
  적어 둔다.
- 공용 하네스는 `e2e/support/`: `restMock.ts`(REST) · `fakeGameServer.ts`(WS 서버) ·
  `roomSession.ts`(재접속용 sessionStorage 시딩) · `flows.ts`(공통 흐름) · `contract.ts`.

### E2E

`e2e/`에 `create-room` · `join-room` · `invalid-invite` · `lobby-realtime` · `game-flow` ·
`participant-view` · `reconnect` · `disconnect` · `not-found` 9개 스펙 신설(기존

- 방 생성(호스트) → 대기실(초대 패널·참가자 카드·1인 시작 가능) → 게임 시작 → 굴림·KEEP·
  족보 기록 → 점수 반영 → 게임 종료 → 결과(순위·점수표) → 대기실 복귀

- 잘못된 초대 코드 → 안내 → 코드 수정 재참가
- 대기실 실시간 브로드캐스트(입장/퇴장/presence), 방 종료 시 홈 복귀
- 참가자 시점 관전(상대 굴림 반영), 대기실 복귀 팔로우
- 재접속: sessionStorage 복원 → 재조인, 세션 불일치·이탈 처리
- 연결 끊김: 재연결 표시 → 자동 복구, WS 에러 코드(SESSION_EXPIRED)로 세션 종료

**135/135 통과** — mobile-chrome · mobile-safari · desktop-chrome 3개 프로젝트 전부.

### 그 밖의 정리

- `biome.json`에 `!coverage` 제외 추가 — `dist`·`playwright-report`·`test-results`는 이미
  제외였는데 `coverage`만 빠져 있어서, `--coverage`를 한 번이라도 로컬에서 돌리면
  `npm run check`가 생성된 HTML 리포트를 파싱하려다 수백 건의 가짜 에러를 냈다.
- `playwright.config.ts`: `testMatch: '**/*.spec.ts'`(support 폴더가 스펙으로 오인되지
  않게 명시), `reporter`를 `html` 기본값(`open: 'on-failure'`— 로컬 실행 실패 뒤 리포트
  서버가 프로세스를 붙잡는다) 대신 `[['list'], ['html', { open: 'never' }]]`로 조정.
- 전체 검증 통과: `npm run check` · `npm run typecheck` · `npm test` · `npm run build` ·
  `npm run test:e2e`.

## 남은 것 · 한계

이 브랜치의 목표(90%+ 커버리지, 다양한 E2E 시나리오)는 달성했지만, 아래는 이 작업만으로는
채워지지 않는 부분이다 — 다음 단계(리팩토링·QA)에서 참고할 것.

- **발견했지만 고치지 않은 버그 3건.** 이 브랜치는 소스를 건드리지 않기로 했으므로 아래를
  테스트로 고정하지 않고 기록만 남겼다. 리팩토링 브랜치에서 다뤄야 한다.
  1. `RecordPanel.tsx:94-96` — peek 상태에서 드래그하면 패널이 튄다. 인라인
     `transform: translateY(Math.max(0, dragOffset))`이 peek 클래스
     `translate-y-[calc(100%-8.5rem)]`을 덮어써서, 접힌 상태에서 위로 1px만 끌어도
     완전히 열린 위치로 점프하고 임계값(56px) 미달이면 다시 튀어 내려온다.
  2. `BottomSheet.tsx:117` · `RecordPanel.tsx:106` — `onPointerCancel`이 `onPointerUp`과
     같은 핸들러라, 시스템 제스처가 포인터를 가로채 취소해도 임계값을 넘긴 상태면 시트가
     닫힌다. 취소는 원위치가 자연스럽다.
  3. `RecordPanel.tsx:61-72` — 드래그 종료 직후 click이 이어져 `onToggle`이 한 제스처당
     두 번 불린다. 지금은 `onToggle`이 절대값 boolean이라 무해하지만, 토글 형태로
     리팩터링하면 즉시 깨진다.
- **개발 전용 UI는 커버리지에서 완전히 빠져 있다.** `DevCatalog` · `PhysicsDiceDemo` ·
  `MotionLab*` 화면들(설계 절 참고). 지금은 의도된 제외지만, 이 화면들이 실기기 QA나
  운영 도구로 계속 쓰인다면 별도로 테스트를 붙여야 한다.
- **100%가 아니다.** 남은 미커버 지점은 대부분 도달 불가한 방어 분기(`?? ''` 폴백,
  `typeof window === 'undefined'`, ref null 가드)이거나 Rapier 물리 시뮬레이션의 드문 분기
  (`World.ts:341`)다. `GameResult.tsx`(분기 68%) · `RealtimeSync.tsx`(분기 79%) ·
  `useGameApi.ts`(분기 83%)처럼 분기 커버리지가 상대적으로 낮게 남은 파일도 있다 — 라인은
  90%를 넘지만 에러 조합까지 전부 짚지는 못했다.
- **E2E의 WS 계약은 손으로 미러링한 것이다.** `e2e/support/contract.ts`는
  `src/realtime/wsEvents.ts`를 그대로 import할 수 없어서 필드만 옮겨 적었다. 실제 계약이
  바뀌어도 이 미러가 자동으로 깨지지 않는다 — 계약 변경 시 이 파일도 함께 고쳐야 한다는
  걸 사람이 기억해야 한다.
- **Playwright 에뮬레이션이지 실기기가 아니다.** `mobile-chrome`·`mobile-safari` 프로젝트는
  Pixel 7·iPhone 15 뷰포트/UA 에뮬레이션이다. 흔들기 센서(모션 제스처) 입력 자체는 실기기
  브라우저에서만 발생하므로 E2E로 검증하지 못했다(유닛 테스트에서 `useMotionRollInput` 등을
  모킹해 로직만 확인).
- **시각 회귀·접근성 감사·부하 테스트는 이 작업 범위 밖이다.** 필요하면 별도 티켓으로.
- **백엔드 통합은 다루지 않는다.** 이 안전망은 프론트엔드 단독 계약(REST/WS mock) 기준이다.
  실제 백엔드가 계약과 어긋나면 이 테스트들은 잡아내지 못한다.
