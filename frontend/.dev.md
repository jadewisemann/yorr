## 1. 목표

현재 프론트엔드의 한 단계 레이어 구조와 서버 권위 상태 모델은 유지한다. 대신
`GamePlay.tsx`에 함께 들어 있는 굴림, 센서 입력, 관전 동기화, 점수 제출, 화면 조립을
생명주기 단위로 정리해 코드가 위에서 아래로 선언적으로 읽히게 한다.

완료 후 `GamePlay`는 다음 순서로 읽혀야 한다.

1. 서버 스냅샷과 화면 입력을 받는다.
2. 굴림 훅과 제출 훅에서 상태와 명령을 얻는다.
3. 단순 파생값을 계산한다.
4. 헤더, 턴 표시, 주사위 트레이, 액션, 점수 패널을 조립한다.

코드 줄 수 자체보다 다음을 우선한다.

- 서버 권위 상태와 로컬 연출 상태의 경계가 명확할 것
- 관련된 이벤트 순서와 pending ref가 한 생명주기 안에 있을 것
- 이름만 읽어도 의도를 알 수 있을 것
- 변경 단위와 커밋이 작아 리뷰와 되돌리기가 쉬울 것
- 기존 동작과 사용자 경험을 임의로 바꾸지 않을 것

## 5. 실시간 불변식

리팩터링 전후에 다음 불변식을 유지한다.

- 소켓 open과 방 JOIN 복구 완료는 같은 상태가 아니다.
- JOIN 승인 또는 권위 snapshot을 받기 전에는 오래된 게임 상태로 명령을 보내지 않는다.
- 서버의 `rollCount`, `dice`, `held`, 점수는 클라이언트 로컬 계산보다 우선한다.
- 다른 방, 다른 라운드, 비활성 플레이어의 굴림은 현재 턴에 반영하지 않는다.
- 과거 `rollCount` 메시지로 현재 snapshot을 퇴행시키지 않는다.
- `dice.broadcast`와 `dice.thrown`의 도착 순서가 바뀌어도 한 번만 release한다.
- 센서 throw가 broadcast보다 먼저 와도 broadcast 도착 뒤 같은 request를 release한다.
- 점수 ACK/error는 pending `msgId`가 일치할 때만 현재 제출을 종료한다.
- 턴이 바뀌면 이전 턴의 pending roll, submission, remote release를 폐기한다.
- reconnect, close, heartbeat timer는 한 연결 수명에 하나씩만 존재한다.
- 서버가 종료를 명령한 세션은 무한 재연결하지 않는다.
