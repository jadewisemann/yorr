## 1. 목표

참조 데모의 Three.js·Rapier 주사위 장면을 현재 TypeScript 애플리케이션에 이식한다.
이식 결과는 게임 규칙이나 세션을 스스로 판단하지 않고, 호출자가 전달한 굴림 계획을
시각화하는 **결과 입력형 렌더러**다.

이번 작업에서 동시에 달성해야 하는 목표는 다음과 같다.

1. 참조 데모의 사발, 트레이, 주사위, KEEP 슬롯, 굴림과 결과 정렬의 외형과 동작을 보존한다.
2. 1,554줄의 React·Three.js·Rapier 결합 파일을 현재 저장소의 레이어와 파일 규칙에 맞게 나눈다.
3. `requestId`, `seed`, `targetDice`, `held`를 입력받아 목표 결과를 보장한다.
4. React 생명주기와 명령형 3D 월드를 분리한다.
5. idle RAF 중단, resize 안정화, unmount 자원 해제와 실패 fallback을 제공한다.
6. 이후 게임 화면과 센서 입력이 렌더러 내부를 수정하지 않고 같은 계약을 사용할 수 있게 한다.

이 계획에서 “모듈화”는 코드를 가능한 한 잘게 쪼개는 작업을 뜻하지 않는다. 변경 이유와
의존성이 다른 경계만 분리하고, 서로 강하게 결합된 물리 시뮬레이션 단계는
`PhysicsDiceWorld` 안에서 순서를 보존한다.

## 2. 기준과 우선순위

구현 판단이 충돌하면 아래 순서를 따른다.

1. Jira 73의 완료 조건과 이 문서의 렌더러 계약
2. 현재 코드의 `src/domain/dice.ts` 굴림 계획 계약
3. 현재 저장소의 레이어·import·스타일 규칙
4. 참조 데모의 정상 환경 3D 외형과 동작
5. 참조 데모의 파일 구성과 구현 방식

즉, 원본의 **사용자에게 보이는 결과와 움직임**은 보존하지만 원본의 React 상태 구조,
로컬 게임 세션, 설정 패널, localStorage 방식까지 그대로 복사하지는 않는다.

## 3. 원본 분석과 보존 대상

### 3.1 원본 구성

`docs/ref/frontend/src/ui/PhysicsDiceScene.jsx`에는 아래 책임이 한 파일에 결합되어 있다.

- Rapier WASM 초기화와 world 생성
- Three.js scene, camera, renderer, light 생성
- 트레이 mesh와 고정 collider 생성
- 사발 mesh와 kinematic collider 생성
- 주사위 geometry, pip, material, rigid body와 collider 생성
- KEEP 슬롯 geometry와 레이아웃 계산
- 테마 색상 동기화
- resize observer와 camera frustum 계산
- pointer raycast와 KEEP 입력
- 흔들기, 사발 기울이기, 쏟기, 트레이 경계 보정
- 물리 정지 판정과 결과 눈 계산
- 결과 quaternion 정렬과 확대 애니메이션
- RAF invalidation
- React effect, callback 최신화, 오류와 resize UI
- Three.js와 Rapier 자원 정리

원본의 `GameScreen.jsx`, `PhysicsSettingsPanel.jsx`, 로컬 game/session 파일은 렌더러
자체가 아니므로 이식 대상에서 제외한다.

### 3.2 외형 불변 항목

아래 항목은 임의로 개선하거나 재디자인하지 않는다.

- orthographic camera 방향과 simulation/result frustum 계산
- hemisphere light, directional light, tone mapping, exposure와 soft shadow
- 주사위 크기, 둥근 모서리 비율, collider 비율과 pip 크기·간격
- 1의 빨간 눈과 나머지 어두운 눈의 면 배치
- 트레이 크기, rim, separator, 굴림 영역과 KEEP 슬롯 위치
- 사발 lathe profile, rim, 내부 색상, collider 수와 배치
- 주사위의 simulation scale, result scale과 결과 행 간격
- 선택 outline과 KEEP outline의 크기, 투명도와 이동 방식
- 결과 정렬 중 lift, scale overshoot, camera zoom

색상은 현재 디자인 시스템의 semantic token을 통해 공급하되, 원본 fallback 색과 명암 관계를
보존한다. 현재 token만으로 같은 표현이 불가능하면 렌더러 전용 semantic token을
`src/styles/index.css`의 `@theme`에 추가하고 원시 색을 컴포넌트 class에 직접 넣지 않는다.

### 3.3 동작 불변 항목

아래 정상 모션의 단계와 원본 설정값을 유지한다.

```text
idle
  → shaking
  → pouring
  → 물리 정지 판정
  → aligning
  → idle + 완료 callback
```

- 사발 오른쪽 시작 위치와 흔들림 주기·진폭
- 버튼 명령 또는 2.4초 후 자동 기울이기
- 왼쪽으로 사발을 넘기고 주사위를 쏟는 방향
- 투척 속도, impulse, torque와 fan 분산
- 트레이 밖으로 이탈한 주사위의 안전 보정
- 속도·각속도 기준 20 stable frame 또는 최대 4.8초 정지 판정
- 900ms 결과 정렬과 KEEP 슬롯 380ms 이동
- 굴림 중 KEEP 주사위의 물리 제외와 고정 슬롯 유지

정상 모션에서 달라지는 부분은 최종 결과의 권위뿐이다. 원본은 Rapier가 만든 윗면을 결과로
사용하지만 이식본은 같은 물리 연출을 마친 뒤 `targetDice`에 해당하는 quaternion으로 정렬한다.
따라서 궤적과 연출은 유지하면서 게임 결과는 호출자가 소유한다.

### 3.4 원본 설정 이식 원칙

`docs/ref/frontend/src/config/physics.json`의 아래 값을 이름과 수치 변경 없이 typed constant로
옮긴다.

- 기본 물리값: 크기, 질량, 중력, 마찰, 반발, 감쇠, 투척 세기, simulation Hz
- ECO/BALANCED/HIGH pixel ratio, shadow 사용 여부와 shadow map 크기
- tray, keepSlots, bowl, alignment, camera, safety 설정

사용자가 조절하는 `PhysicsSettingsPanel`은 제품 렌더러 범위가 아니다. 품질 preset과 필요한
물리 설정은 typed prop 또는 기본 설정으로만 제공한다. 기본값은 원본 `balanced`로 두어
기본 외형을 바꾸지 않는다.

## 4. 현재 저장소에 맞춘 레이어 구조

### 4.1 추가할 레이어

Three.js와 Rapier는 UI 컴포넌트나 게임 도메인이 아니라 브라우저 렌더링 인프라다.
실제 구현 파일이 생기므로 `src/rendering/` 레이어를 추가한다.

일반적인 렌더링 파일은 기존 규칙대로 `src/rendering` 한 단계에 둔다. 다만 이번 subsystem은
Three.js 장면, Rapier 물리, 레이아웃과 자원 생명주기가 하나의 public API를 구성하고 파일
이름마다 `PhysicsDice` 접두사가 반복된다. 사용자 요청에 따라 이 기능에 한해서
`src/rendering/physics-dice/`를 **단일 기능 경계**로 사용한다. 이 폴더 아래에 추가 하위
폴더는 만들지 않으며, 외부에서는 `World.ts`와 `types.ts`만 직접 사용한다.

```text
src/
  app/
    DevCatalog.tsx
    PhysicsDiceDemo.tsx          # 개발 전용 계약·상태 검증 하네스
  components/
    Dice.tsx                     # 기존 2D 주사위, fallback에서 재사용
    PhysicsDiceFallback.tsx      # 실패·모션 감소 시 결과 보장
    PhysicsDiceScene.tsx         # React wrapper와 lazy engine 경계
  domain/
    dice.ts                      # 기존 RollPlan SSOT, 변경하지 않음이 기본
    yachtGame.ts                 # 호출자 상태 전이, 렌더러가 import하지 않음
  rendering/
    physics-dice/
      World.ts                   # public 명령형 API와 phase 오케스트레이션
      types.ts                   # 렌더러 독립 입력·출력 타입
      config.ts                  # 원본 physics.json typed 설정
      model.ts                   # 공유 geometry, material, 면 quaternion
      random.ts                  # seed 기반 연출 난수
      stage.ts                   # scene, camera, light, renderer 생성
      arena.ts                   # tray, bowl, KEEP 슬롯과 고정 collider
      diceInstances.ts           # 주사위 mesh, body, collider 인스턴스
      layout.ts                  # 결과 행·KEEP 배치와 보간
      safety.ts                  # bowl/tray 이탈 보정
      interaction.ts             # pointer raycast
      appearance.ts              # 테마 동기화와 GPU 자원 해제
      runtimeTypes.ts            # subsystem 내부 객체 타입
  styles/
    index.css                    # 필요한 renderer semantic token과 fallback animation
```

각 파일명은 폴더 문맥을 이용해 짧게 유지하되 `utils`, `helpers`, `manager`, `service`처럼
책임이 드러나지 않는 이름은 사용하지 않는다. `World.ts`만 orchestration 상태를 변경하며,
나머지는 생성 결과를 반환하거나 전달받은 객체에 한정된 변환을 수행한다. 이 경계 덕분에
폴더 밖에는 Three.js/Rapier 내부 타입이 노출되지 않는다.

### 4.2 레이어별 책임

#### `src/domain`

- 게임 결과와 KEEP 규칙의 권위자
- seed로 `targetDice`를 계획
- 처리 중인 `requestId`와 완료된 주사위 상태 관리
- 렌더러 완료 전 `targetDice`를 현재 주사위로 확정하지 않음

`src/domain`은 Three.js, Rapier, React와 `src/rendering`을 import하지 않는다.

#### `src/rendering`

- 명령형 canvas와 physics world 관리
- 전달받은 목표 결과를 시각화
- 입력된 `seed`를 연출용 난수로만 사용
- pointer hit 결과를 index로 반환
- 게임 규칙, 제출, 라운드, 네트워크를 모름

`src/rendering`은 `src/domain`, `src/screens`, `src/components`, `src/realtime`,
`src/store.ts`를 import하지 않는다.

#### `src/components`

- React props를 명령형 world 호출로 번역
- 브라우저 capability와 모션 감소 여부에 따라 3D/fallback 선택
- callback 최신화와 effect cleanup
- 사용자에게 접근 가능한 상태와 오류 메시지 제공

컴포넌트는 게임 reducer를 직접 호출하지 않는다. 호출자가 callback으로 상태 전이를 연결한다.

#### `src/app`

- 개발 환경에서만 실행되는 renderer harness 제공
- 선행 `planRoll()`과 renderer props를 연결하여 실제 계약을 검증
- 품질 preset, KEEP, 연속 request, 실패 fallback을 수동 확인

실제 `GamePage` 통합은 후속 게임 화면 작업과 충돌하지 않도록 이번 티켓에서 하지 않는다.

## 5. 모듈별 상세 설계

### 5.1 `types.ts`

렌더러가 domain 타입을 import하지 않도록 구조적으로 호환되는 최소 계약만 정의한다.

```ts
export type PhysicsDiceValue = 1 | 2 | 3 | 4 | 5 | 6

export type PhysicsDiceSet = readonly [
  PhysicsDiceValue,
  PhysicsDiceValue,
  PhysicsDiceValue,
  PhysicsDiceValue,
  PhysicsDiceValue,
]

export type PhysicsHeldDice = readonly [boolean, boolean, boolean, boolean, boolean]
export type PhysicsDiceIndex = 0 | 1 | 2 | 3 | 4
export type PhysicsDiceQuality = 'eco' | 'balanced' | 'high'
export type PhysicsDicePhase = 'idle' | 'shaking' | 'pouring' | 'aligning'

export interface PhysicsDiceRollRequest {
  requestId: string
  seed: number
  targetDice: PhysicsDiceSet
  held: PhysicsHeldDice
}
```

React public props는 “현재 확정 상태”와 “처리할 명령”을 구분한다.

```ts
interface PhysicsDiceSceneProps {
  dice: PhysicsDiceSet | null
  held: PhysicsHeldDice
  request: PhysicsDiceRollRequest | null
  quality?: PhysicsDiceQuality
  onHeldToggle?: (index: PhysicsDiceIndex) => void
  onRollComplete: (requestId: string) => void
  onPhaseChange?: (phase: PhysicsDicePhase) => void
  onError?: (error: Error) => void
}
```

`dice`는 reducer가 확정한 현재 값이고 `request.targetDice`는 애니메이션 종료 후 확정할 값이다.
이 둘을 분리하여 굴림 완료 전에 목표 결과가 화면이나 게임 상태에 노출되는 것을 막는다.

`src/domain/dice.ts`의 `RollPlan`은 추가 adapter 없이 `PhysicsDiceRollRequest`에 구조적으로
대입 가능해야 한다. 렌더러 계약에 `nextSeed`를 넣지 않는다. `nextSeed`는 domain 상태 전이용이며
연출에 필요하지 않다.

### 5.2 `config.ts`

- 원본 JSON을 `as const` typed object로 옮긴다.
- runtime JSON fetch나 설정 panel 의존성을 만들지 않는다.
- 품질 preset 조회와 기본 설정 병합처럼 부작용 없는 작은 함수만 제공한다.
- 렌더러 동작 수치는 이 파일 외부에 흩어놓지 않는다.
- 원본과 다른 안전 timeout이 필요하면 별도 이름으로 추가하고 근거를 주석으로 남긴다.

### 5.3 `model.ts`

주사위 한 개의 시각 모델과 면 방향만 담당한다.

- `FACE_NORMALS`, `PIPS`
- `quaternionForTopValue`
- `topFaceFromQuaternion`
- rounded rectangle geometry
- rounded box body와 instanced pip 생성
- 1번 눈의 red material과 나머지 pip material 배치
- die index를 raycast 가능한 `userData`에 저장

이 모듈은 scene, RAF, React, Rapier world와 굴림 phase를 모른다. Three.js 형상 생성과
면 방향이라는 한 가지 이유로만 변경된다.

### 5.4 `random.ts`

원본의 `Math.random()` 호출 위치와 분포를 유지하면서 입력 source만 seed 기반 generator로
바꾼다.

- spawn radius jitter
- 초기 spawn 높이
- 초기 linear/angular velocity
- shake impulse와 torque
- spill speed, fan, side impulse와 torque

동일한 `seed`와 같은 held mask는 같은 연출 파라미터를 만든다. 이 난수는 목표 눈을 생성하지
않으며 게임 결과에 영향을 주지 않는다. 난수 호출 순서는 원본의 단계 순서를 보존한다.

### 5.5 `World.ts`

이 파일은 명령형 3D subsystem의 유일한 public class다.

외부 public API는 작게 유지한다.

```ts
class PhysicsDiceWorld {
  init(): Promise<void>
  syncCommittedDice(dice: PhysicsDiceSet | null, held: PhysicsHeldDice): void
  startRoll(request: PhysicsDiceRollRequest): void
  pour(): void
  applyQuality(quality: PhysicsDiceQuality): void
  resize(): void
  destroy(): void
}
```

내부 구현은 원본의 시간 순서가 읽히도록 다음 순서로 배치한다.

1. 초기화와 scene asset 생성
2. resize와 layout 계산
3. committed dice와 KEEP 동기화
4. 굴림 시작과 사발 배치
5. 흔들기와 pour
6. physics step과 안전 경계
7. 정지 판정
8. target 결과 정렬
9. pointer picking
10. invalidate와 destroy

강하게 결합된 `updateBowl`, `releaseFromBowl`, `checkSettled`와 phase 완료 처리는
`World.ts`에 남긴다. 이 메서드들은 같은 Rapier world, frame clock, seeded random과 phase를
공유하며 **호출 순서 자체가 동작 계약**이기 때문이다. 반면 객체 생성과 공간 계산은 아래
모듈로 분리한다.

| 모듈 | 책임 | 변경 가능한 이유 |
|---|---|---|
| `stage.ts` | scene·camera·light·renderer 생성 | 초기화 결과만 반환하며 phase를 모름 |
| `arena.ts` | tray·bowl·KEEP 슬롯과 collider 생성 | 원본 상수를 그대로 소비하는 정적 구성 |
| `diceInstances.ts` | 5개 mesh·body·collider 생성 | 인스턴스 생성 순서와 설정을 한곳에 고정 |
| `layout.ts` | 결과 행·KEEP 위치·보간 적용 | 입력 객체에 결정론적으로 배치 적용 |
| `safety.ts` | bowl/tray 이탈 보정 | 한 physics step 뒤 위치·속도만 보정 |
| `interaction.ts` | pointer raycast로 die index 반환 | 게임 상태를 모르고 index만 반환 |
| `appearance.ts` | semantic token 동기화와 dispose | 시각 자원만 소유하고 phase를 모름 |

`World.ts`는 위 모듈의 반환 객체를 조립하고 `frame()`에서 호출 순서를 결정한다. 하위 모듈은
서로를 import하지 않으며 `World.ts`로 callback하지 않는다. 따라서 의존은
`World → stage/arena/dice/layout/safety/interaction/appearance` 단방향이다.

#### world 내부 상태 소유권

`PhysicsDiceWorld`가 소유하는 상태:

- factory가 생성한 Three scene, camera, renderer, lights 참조
- Rapier world, bodies와 colliders 참조
- mesh, geometry, material과 outline 참조 및 dispose 시점
- 현재 표시 중인 committed dice와 held mask
- 처리 중인 request와 seeded random
- phase, frame time, accumulator, stable frame
- resize/layout/alignment animation 상태
- 마지막 완료한 request ID

`PhysicsDiceWorld`가 소유하지 않는 상태:

- 굴림 횟수와 다음 seed
- 사용한 점수 카테고리
- 방, 플레이어, 세션과 서버 snapshot
- WebSocket 연결과 메시지
- 현재 게임 화면의 버튼 활성 조건

### 5.6 `PhysicsDiceScene.tsx`

React wrapper는 Three.js나 Rapier 세부 객체를 state로 만들지 않는다.

- container DOM ref
- world instance ref
- 최신 callback ref
- 마지막으로 전달한 request ID ref
- capability/error/resizing 같은 최소 UI state

Three/Rapier bundle은 wrapper import 시 즉시 로드하지 않는다. mount 후
`import('@/rendering/physics-dice/World')`로 engine을 동적 import하여 실제 3D 화면에서만
다운로드한다.

effect 책임은 다음처럼 분리한다.

- mount effect: world 동적 import, init, 초기 sync, cleanup
- committed state effect: `syncCommittedDice(dice, held)`
- request effect: 새 request ID일 때만 `startRoll(request)`
- quality effect: `applyQuality(quality)`
- reduced motion/capability effect: 3D와 fallback 경로 결정

callback prop 변경 때문에 world를 다시 만들지 않는다. callback ref를 갱신하고 world가
완료할 때 최신 ref를 호출한다.

### 5.7 `PhysicsDiceFallback.tsx`

다음 경우에도 게임을 끝낼 수 있는 동일 계약의 fallback을 제공한다.

- WebGL context 또는 renderer 생성 실패
- Rapier WASM import/init 실패
- `prefers-reduced-motion: reduce`

fallback은 기존 `Dice` 5개를 사용해 committed dice와 KEEP을 표현한다. 새 request가 오면
reduced motion에서는 불필요한 회전·흔들기 없이 목표 결과로 전환하고 완료 callback을
한 번 호출한다. 3D 초기화 실패에서는 오류 안내를 제공하되 KEEP과 다음 굴림 흐름을 막지 않는다.

fallback 완료도 `requestId` 기준으로 중복 제거한다.

## 6. 코드 의존 방향

레이어를 넘는 import는 `@/`를 사용하고 같은 폴더에서는 상대경로를 사용한다.

```text
src/app/PhysicsDiceDemo.tsx
  ├─→ @/domain/dice
  └─→ @/components/PhysicsDiceScene

src/components/PhysicsDiceScene.tsx
  ├─→ @/rendering/physics-dice/types
  ├─→ dynamic import @/rendering/physics-dice/World
  └─→ ./PhysicsDiceFallback

src/components/PhysicsDiceFallback.tsx
  ├─→ @/rendering/physics-dice/types
  └─→ ./Dice

src/rendering/physics-dice/World.ts
  ├─→ three
  ├─→ @dimforge/rapier3d-compat
  ├─→ ./stage
  ├─→ ./arena
  ├─→ ./diceInstances
  ├─→ ./layout
  ├─→ ./safety
  ├─→ ./interaction
  ├─→ ./appearance
  ├─→ ./config · ./model · ./random
  └─→ ./types · ./runtimeTypes

src/rendering/physics-dice/{stage,arena,diceInstances,layout,safety,interaction,appearance}.ts
  ├─→ ./config · ./model · ./types · ./runtimeTypes (필요한 항목만)
  └─╳ components · domain · realtime · store
```

금지하는 역방향 import:

```text
rendering → domain
rendering → components
rendering → screens
rendering → realtime
rendering → store
domain → rendering
domain → components
```

이 구조에서 게임 규칙이 바뀌어도 렌더러는 입력 계약만 유지하면 수정되지 않고, Three.js 구현이
바뀌어도 reducer와 WebSocket 계약은 수정되지 않는다.

## 7. 전체 코드 흐름

### 7.1 최초 mount

```text
React 화면
  → PhysicsDiceScene mount
  → 브라우저 capability / reduced motion 확인
  → 3D 가능: PhysicsDiceWorld dynamic import
  → Rapier.init()
  → scene / tray / bowl / dice / keep slot 생성
  → observer / pointer listener 연결
  → committed dice를 idle layout으로 배치
  → 한 프레임 render 후 RAF 중단
```

초기화 중 prop이 바뀌면 wrapper의 latest ref에 저장하고 init 완료 후 최신 값만 sync한다.
unmount가 먼저 발생하면 init 완료 후 scene을 붙이지 않고 종료한다.

### 7.2 굴림 요청

```text
사용자 입력 또는 센서
  → domain: rollRequested(requestId)
  → domain: planRoll(seed, currentDice, held)
  → pending RollPlan 생성
  → 화면이 PhysicsDiceScene.request로 전달
  → wrapper가 requestId 중복 확인
  → world.startRoll({ requestId, seed, targetDice, held })
```

wrapper와 world 모두 request ID를 확인한다. React StrictMode effect 재실행이나 동일 상태
rerender가 발생해도 같은 굴림이 두 번 시작되지 않는다.

### 7.3 3D 시뮬레이션

```text
startRoll
  → held 주사위: fixed body + KEEP slot 유지
  → 나머지 주사위: seeded spawn/velocity + bowl 안 배치
  → phase=shaking
  → invalidate RAF
  → 사용자 pour 또는 autoTilt
  → phase=pouring
  → 사발 tilt + 주사위 release
  → fixed timestep Rapier step
  → tray containment
  → 정지 조건 확인
```

물리 step은 원본과 동일한 fixed timestep을 사용한다. frame delta는 accumulator에 쌓고
resize 중에는 simulation clock을 진행하지 않는다.

### 7.4 목표 결과 확정

```text
물리 정지
  → 각 주사위의 현재 transform을 alignment 시작값으로 저장
  → request.targetDice를 목표 quaternion으로 변환
  → phase=aligning
  → lift + scale overshoot + result row 이동
  → alignment 완료
  → phase=idle
  → world가 requestId 완료 알림
  → wrapper가 아직 미완료인 request인지 확인
  → onRollComplete(requestId)
  → domain: rollCompleted(requestId)
  → targetDice가 committed dice로 확정
```

물리로 우연히 나온 윗면은 디버깅 정보일 수는 있지만 게임 결과로 반환하지 않는다.
완료 callback은 dice 값을 다시 반환하지 않는다. 이미 계획된 `targetDice`를 reducer가 소유하기
때문에 같은 데이터를 두 권위자로 만들지 않는다.

### 7.5 KEEP 변경

```text
idle 상태에서 pointer raycast
  → world가 die index만 wrapper에 전달
  → onHeldToggle(index)
  → domain이 held mask 변경 가능 여부 판단
  → 새 committed held prop
  → world.syncCommittedDice
  → 기존 380ms KEEP slot transition
```

굴림 중 pointer picking은 world에서 차단한다. KEEP 규칙 자체는 domain이 판단한다.

### 7.6 오류와 fallback

```text
dynamic import / Rapier.init / WebGLRenderer 실패
  → 오류를 Error로 정규화
  → 부분 생성된 world.destroy()
  → onError(error)
  → PhysicsDiceFallback 표시
  → 같은 request 계약으로 결과 확정
```

fallback 전환 중 처리 중이던 request도 완료가 유실되거나 두 번 완료되지 않게 request ID
ledger를 wrapper가 유지한다.

## 8. RAF, resize와 자원 수명주기

### 8.1 event-driven RAF

다음 상태에서만 다음 RAF를 예약한다.

- `shaking`
- `pouring`
- `aligning`
- KEEP 또는 idle layout transition
- resize 또는 테마 변경으로 한 번의 redraw가 필요한 상태

`idle`이고 layout transition이 없으면 render 후 RAF를 다시 예약하지 않는다.
`invalidate()`는 이미 예약된 frame이 있으면 중복 요청하지 않는다.

### 8.2 resize

- `ResizeObserver` 이벤트를 원본과 같은 180ms 안정화 시간으로 debounce
- resize 중 skeleton 표시
- 확정된 container 크기로 renderer와 orthographic frustum을 한 번 갱신
- resize 종료 시 `lastTime`과 accumulator 초기화
- 0 크기 container에서는 최소 1px로 계산하고 NaN projection을 만들지 않음
- resize가 정렬 중 발생하면 현재 progress와 목표 layout을 유지

### 8.3 destroy

unmount 시 아래 자원을 모두 정리한다.

- 예약된 RAF와 resize timeout
- `ResizeObserver`, theme `MutationObserver`
- canvas pointer listener
- 모든 geometry와 material
- renderer render list와 renderer
- 필요 시 WebGL context loss
- Rapier world
- container에 추가한 canvas

비동기 Rapier 초기화가 destroy 이후 완료되어도 scene을 생성하거나 callback을 호출하지 않는다.

## 9. 품질 preset과 모션 감소

### ECO

- pixel ratio 1
- shadow 비활성
- 저사양·발열 우려 모바일용

### BALANCED

- pixel ratio 최대 1.5
- shadow 512
- 원본 기본값이자 제품 기본값

### HIGH

- pixel ratio 최대 2
- shadow 1024
- 고성능 기기 또는 개발 시각 검토용

quality 변경은 geometry와 physics world를 다시 만들지 않고 renderer pixel ratio와 shadow만
갱신한다. 물리값이나 카메라 구도를 quality에 따라 바꾸지 않는다.

`prefers-reduced-motion: reduce`에서는 3D 물리 모션 대신 fallback을 사용한다. 결과,
KEEP, callback 계약은 동일하며 모션 감소가 게임 기능 감소로 이어지지 않는다.

## 10. 구현 순서

1. `three`, `@dimforge/rapier3d-compat`를 원본과 호환되는 버전으로 추가한다.
2. `types.ts`로 렌더러 public contract를 먼저 고정한다.
3. `config.ts`에 원본 수치를 손실 없이 옮기고 원본 대비표를 확인한다.
4. `random.ts`에 seed 기반 generator와 원본 분포 adapter를 구현한다.
5. `model.ts`에 주사위 geometry, pip와 face quaternion을 이식한다.
6. `stage`, `arena`, `diceInstances`에 원본 scene asset 생성 코드를 값 변경 없이 이식한다.
7. `layout`, `safety`, `interaction`, `appearance`에 독립 계산과 자원 책임을 분리한다.
8. `World.ts`에서 원본 phase·physics step·난수 호출 순서를 조립한다.
9. 물리 결과 대신 `targetDice` quaternion을 alignment 목표로 연결한다.
10. RAF, resize와 destroy를 안정화한다.
11. `PhysicsDiceFallback.tsx`와 `PhysicsDiceScene.tsx`를 구현한다.
12. 개발 카탈로그에 `PhysicsDiceDemo`를 연결해 독립 계약을 검증한다.
13. 단위·컴포넌트 검증과 원본 대비 시각 검토를 수행한다.

각 단계에서 원본의 동작 상수나 장면 값을 함께 “개선”하지 않는다. 이식과 튜닝을 한 변경에서
섞지 않는다.

## 14. 구현 중 중단하고 재검토할 조건

아래 상황에서는 원본을 임의로 바꾸지 않고 이 계획을 다시 검토한다.

- 현재 semantic token으로 원본과 유사한 명암을 표현할 수 없는 경우
- iPhone Safari에서 원본 geometry 또는 Rapier WASM이 동작하지 않는 경우
- target quaternion 정렬이 기존 alignment 궤적을 눈에 띄게 바꾸는 경우
- `PhysicsDiceWorld` 분리 과정에서 순환 import가 필요한 경우
- 후속 티켓의 GamePage 계약이 이 문서의 props와 충돌하는 경우

이 경우에도 우선순위는 정상 환경의 3D 외형·동작 보존과 renderer/domain 독립성이다.
