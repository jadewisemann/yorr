### OBS-1. 뷰포트 리사이즈 직후 레이아웃 미갱신 (재검증 완료 — 재현 안 됨)

- 제안: 기획 확정값에 맞춰 둘 중 하나 통일(검증에 최소 2자 추가 또는 문구를 1~12자로).

### FND-3. 카테고리 제출 직후 헤더가 "내 턴이에요"를 계속 표시 (경미, 전이 상태)

### 참고. mock 재접속 시 `room.join` 응답이 항상 대기 중 스냅샷으로 고정됨 — 후속 구현에서 해소
**상태: 해소** — 아래 "참고용 개선 아이디어" 그대로, mock이 방 상태를 기억했다가 `room.join` 때 복원한다("후속 구현" 절 참고).
- 증상: 게임 진행 중 새로고침 → "이어서 하기" → 대기실로 이동 후, 실제로는 라운드 진행·점수 기록이 있었음에도 대기실이 "참가 인원 2/6, 온라인"뿐인 신규 대기 상태로 보임(라운드·점수 정보 소실).
- 원인: [`src/mocks/realtimeScenarios.ts`](src/mocks/realtimeScenarios.ts)의 `room.join` 핸들러가 항상 정적 `creatorSession.snapshot`(=`waitingRoomSnapshot`, phase `waiting`)을 반환. [`src/app/RealtimeSync.tsx`](src/app/RealtimeSync.tsx)의 `keepGameState()`는 "서버가 waiting이라 하면 신뢰해서 그대로 따른다"는 의도된 로직이라, 서버(mock)가 매번 waiting을 우기면 진행 상태가 매번 날아감.
- 실제 서버라면 재접속 시 `room.join` 응답이 현재 진짜 phase(`playing`)를 정확히 돌려주므로 재현되지 않을 것으로 판단됨 — FE 코드 결함이 아니라 mock 픽스처의 정적 응답 한계.
- 참고용 개선 아이디어(선택): mock도 실제 방 상태(마지막 `playingRoomSnapshot`)를 들고 있다가 `room.join` 때 그걸 돌려주면, 새로고침 후 재접속 시나리오를 mock만으로도 온전히 검증할 수 있음.

### FND-4. 대기실 초대 카드가 375px 모바일 폭에서 가로 스크롤 유발 (실제 버그, 중간)
**상태: 수정 완료** — 행·텍스트 컨테이너 둘 다에 `min-w-0` 추가, 방 코드 폰트를 `clamp()`로 가변화하고 `truncate`를 안전망으로 추가. 6자·12자 코드 양쪽 다 375px에서 overflow 없음 확인. [`InvitationPanel.tsx`](src/components/InvitationPanel.tsx)
- 재현: 모바일 375×812로 리사이즈 → 방 생성 → 대기실(`/rooms/YORR64/lobby`) 진입 시 `document.documentElement.scrollWidth`(425px) `>` `clientWidth`(375px) — 페이지 전체가 가로로 밀림.
- 원인: [`src/components/InvitationPanel.tsx:55-63`](src/components/InvitationPanel.tsx:55)의 QR+텍스트 가로 배치(`flex items-stretch gap-4`)에서, 방 코드를 담은 `<div className="grid gap-1">`(라인 56)에 `min-w-0`이 없음. 부모는 `min-w-0 flex-1`이라 줄어들 수 있지만, CSS Grid 아이템은 기본적으로 `min-width: auto`(= 내용 기준 최소폭)라 `font-mono text-4xl`(36px) 방 코드 문자열의 렌더링 폭보다 더 줄어들지 않는다. 결과적으로 QR(7.375rem 고정) + gap-4 + 방 코드 열의 최소폭 합이 375px보다 커져 행 전체가 넘친다.
- 재현 폭 확인: 6자 코드(`YORR64`) 기준으로도 이미 넘침 발생 — 방 코드는 최대 12자([`src/roomCode.ts`](src/roomCode.ts) `ROOM_CODE_MAX_LENGTH`)까지 가능해 실제로는 더 크게 넘칠 수 있음.
- 영향: `current-baseline.md`에 명시된 지원 기기(갤럭시 Chrome·iPhone Safari)의 좁은 화면에서 대기실 진입 시 카드가 잘리거나 페이지가 가로로 밀리는 사용자 경험 저하.
- 제안: 방 코드를 담은 grid 컨테이너(또는 `YORR64` span)에 `min-w-0`을 추가하고, 필요하면 좁은 화면에서 폰트 크기를 한 단계 낮추거나(`text-3xl` 등) `break-all`/`truncate`를 함께 고려.
- 참고: 같은 화면의 게임 진행(`/rooms/YORR64/game`) 페이지는 375px에서 가로 넘침 없음 — 대기실 전용 이슈.
- (2026-07-30 추가) 사용자가 직접 QA에서 짚은 6번("모바일에서 불필요한 좌우·상하 스크롤")이 이 항목과 동일 증상으로 확인됨 — 아래 "사용자 제보 재검증" 절 참고.

### FND-5. 상대 턴 종료 후 점수시트가 자동으로 닫히지 않음 (실제 버그, 확정 재현) — 사용자 제보 1번
**상태: 수정 완료** — activePlayerId 변경 이펙트에 `setSheetOpen(false)` 추가. vitest로 라이브 재현과 같은 시나리오(3회 굴림 관전 → 턴 복귀 → 시트 닫힘)를 회귀 테스트로 고정. [`GamePlay.tsx`](src/screens/GamePlay.tsx)
- **재현(라이브, mock에 `round.start`/`dice.broadcast`/`score.update` 직접 주입)**: 참가자 턴으로 전환 → 참가자가 3회 굴림 마침(점수시트 자동 오픈, `aria-expanded="true"`) → 참가자가 점수 확정(`score.update`+`round.end`) → 턴이 나에게 복귀(`round.start`, 헤더는 "내 턴이에요"로 정확히 갱신됨) → 그런데 점수시트는 계속 `aria-expanded="true"`로 열린 채 유지됨. 시트 타이틀도 "기록 — 나"로 바뀌지만 닫히지는 않음.
- 원인: [`src/screens/GamePlay.tsx:69`](src/screens/GamePlay.tsx:69) `sheetOpen`을 닫는 경로는 딱 하나 — 라인 218, **내가 직접 제출한** `round.submit`의 응답(`score.update` + `pending.msgId` 일치)일 때뿐. 턴 주인이 바뀌는 걸 감지하는 [`GamePlay.tsx:101-108`](src/screens/GamePlay.tsx:101) 이펙트(`activePlayerId` 변경 시 로컬 굴림 상태 리셋)에는 `setSheetOpen(false)`가 없다. 즉 **내 턴이 아닐 때(관전) 열린 시트는 그 어떤 경로로도 자동으로 닫히지 않는다** — 사용자가 손으로 아래로 끌어내리거나 바깥을 탭해야만 닫힘.
- 라인 462-465의 자동 오픈 이펙트(`local.rollCount >= MAX_ROLLS`일 때 `setSheetOpen(true)`)는 `isMyTurn` 여부를 따지지 않고 걸려 있어 상대 턴에도 그대로 동작한다 — 관전 중 상대의 점수판을 보여주려는 의도(타이틀이 "기록 — {상대 닉네임}"으로 바뀜)까지는 맞지만, 닫는 짝이 빠져 있다.

## 2. 목표

1. 로컬에서 실제 백엔드(Spring Boot, `backend/`)를 띄우고 프론트가 그 서버를 바라보는
   **real-server 실행 모드**를 만든다.
2. 그 모드 위에서 도는 **광범위한 Playwright E2E 스위트**를 추가한다
   (기존 MSW-독립 스모크는 유지).
3. **테스트 커버리지 리포트/임계값**을 셋업하고 현재 수치를 기록한다.
4. **순환 복잡도(cyclomatic/cognitive complexity)와 순환 참조(circular import) 지표**를
   측정해 리팩토링 대상을 선정하고, 리팩토링 전에 그 대상을 고정하는
   **특성화(characterization) 테스트**를 셋업한다.

리팩토링 자체는 이 티켓 범위가 아니다. 이 티켓은 "리팩토링을 안전하게 시작할 수 있는
테스트 기반"까지만 만든다.

## 3. 단계별 계획

### 3.1 실제 서버 경로 추가 (개발 환경)

**백엔드 실행 (수정 없이 사용만):**

```bash
cd backend && docker compose up -d   # 의존 인프라(DB 등)
./gradlew bootRun                    # localhost:8080
```

**프론트 변경:**

- `vite.config.ts`에 dev/preview 공용 proxy 추가:
  - `/api` → `http://localhost:8080` (REST)
  - `/ws` → `ws://localhost:8080` (`ws: true`, WebSocket)
  - 대상 주소는 `VITE_BACKEND_ORIGIN` 환경변수로 오버라이드 가능하게 한다
    (기본 `http://localhost:8080`)
- `.env.example`에 실서버 모드 예시 추가:

  ```bash
  # 실서버 모드: MSW 끄고 proxy로 백엔드 직결
  VITE_ENABLE_MSW=false
  VITE_BACKEND_ORIGIN=http://localhost:8080
  VITE_WS_URL=/ws/v1/game   # 상대경로면 same-origin proxy를 타도록 realtimeClient 확인
  ```

- `realtimeClient.ts`가 절대 `ws://` URL만 받는다면 상대경로(`/ws/...`)를
  `location.origin` 기준으로 해석하는 분기를 추가한다 (이 티켓에서 유일한 src 코드 변경).
- `package.json` 스크립트 추가:
  - `dev:real` — `VITE_ENABLE_MSW=false vite` (cross-env 필요 시 devDependency 추가)

**완료 조건:** MSW 끈 상태로 `npm run dev:real` → 브라우저에서 방 생성이 실제 백엔드
응답으로 성공한다.

### 3.2 E2E 하네스 이원화 (mock / real)

Playwright 설정을 **두 개의 실행 모드**로 나눈다. 기존 스펙은 그대로 mock 모드에 남긴다.

```
e2e/
  mock/          # 기존 smoke.spec.ts, landing.spec.ts 이동 — 서버 없이 UI 계약만
  real/          # 신규 — 실제 백엔드 필수
  support/       # 공용 헬퍼 (방 생성, 참가, 셀렉터 상수)
  preview-server.mjs
```

- `playwright.config.ts`:
  - `E2E_TARGET=real`일 때 `testDir: e2e/real`, webServer가 proxy 켜진 preview
    (또는 dev 서버)를 실행, `VITE_ENABLE_MSW=false`
  - 기본(mock)일 때 현재와 동일
  - real 모드 시작 전 `http://localhost:8080` health check로 백엔드 미기동이면
    명확한 에러 메시지로 즉시 실패시킨다 (globalSetup)
- 프로젝트(브라우저) 매트릭스는 현행 유지: mobile-chrome · mobile-safari · desktop-chrome
- `package.json` 스크립트:
  - `test:e2e` — 기존 (mock)
  - `test:e2e:real` — `E2E_TARGET=real playwright test`

**real 모드 격리 원칙:**

- 각 테스트가 자기 방을 새로 만들고 그 방 코드로만 상호작용한다 (전역 상태 공유 금지)
- 서버 데이터를 직접 정리하는 API가 없으므로 "방은 일회용"으로 취급한다
- 다중 사용자 시나리오는 `browser.newContext()` 2개(호스트/게스트)로 구성한다

### 3.4 커버리지 셋업

- `package.json`: `test:coverage` — `vitest run --coverage`
- `vitest.config.ts` coverage 설정 보강:
  - `reporter: ['text', 'html', 'lcov', 'json-summary']` (CI·후속 도구 연계용)
  - `include: ['src/**']`, 제외: `src/mocks/**`, `src/test/**`, `*.test.*`,
    `src/vite-env.d.ts`, `src/main.tsx`
  - 3D 렌더링(`src/rendering/**`)은 jsdom에서 의미 있는 커버리지가 안 나오므로
    측정은 하되 임계값 산정 근거에서 분리해 기록한다
- **임계값은 "현재 측정값 - 소폭 여유"로 시작**한다 (ratchet 방식). 도달 불가능한 80%
  같은 값을 걸어 CI를 즉시 깨뜨리지 않는다. 첫 측정 후 `thresholds`를 커밋에 포함한다.
- 측정 결과(전체/레이어별 %)를 이 문서 하단 "측정 기록" 절에 追記한다.
