## MVP 범위

MVP는 파티 모드가 아니라 온라인 프라이빗 룸 모드만 제공한다.

- 방 생성 요청은 기존 REST 계약의 `mode: "online"`을 사용한다.
- 링크·QR·방 코드로 초대받은 2~6명이 각자의 기기에서 참가한다.
- 방 생성자는 호스트이며 대기실에서 게임을 시작할 수 있다.
- 참가자는 호스트가 시작할 때까지 대기한다.
- 게임 시작 후 모든 사용자는 동일한 `/rooms/:roomId/game` 화면으로 이동한다.
- 별도의 호스트 대시보드와 참가자 컨트롤러 화면을 만들지 않는다.
- 파티 모드와 빠른 대전은 MVP 범위에서 제외한다.

## 계약 원칙

- REST 요청·응답과 WebSocket 이벤트 이름·payload를 프론트 편의를 위해 변경하지 않는다.
- 서버가 방·게임·점수 상태의 권위자다.
- 생성/참가 호출 문맥으로만 프론트 내부 `membershipRole`을 부여한다.
  - 방 생성 성공: `host`
  - 방 참가 성공: `participant`
- `membershipRole`은 서버 응답 필드가 아니며 mock REST 응답에도 포함하지 않는다.
- WebSocket 프로토콜 버전과 이벤트 타입은 `src/realtime/wsEvents.ts`를 그대로 따른다.

## S15P11A406-72 완료 기준

1. 온라인 모드로 방을 생성한다.
2. 호스트만 대기실의 게임 시작 버튼을 사용할 수 있다.
3. 참가자는 호스트 시작 전까지 대기 안내를 본다.
4. 게임이 시작되면 호스트와 참가자 모두 공용 게임 경로로 이동한다.
5. 프론트 내부 권한은 새 REST·WebSocket 필드 없이 저장·복구된다.
6. 관련 단위 테스트, 타입 검사, 정적 검사와 빌드가 통과한다.
